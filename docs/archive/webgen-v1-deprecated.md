## 1. ภาพรวม

**แนวคิดในประโยคเดียว**
ร้านค้าเล็กในไทยคุยกับ LINE OA ของระบบเป็นภาษาไทย แล้วได้เว็บไซต์หน้าร้านที่ใช้งานได้ทันที และ**อัปเดตเว็บต่อได้ด้วยการส่งข้อความหรือรูปใน LINE** โดยไม่ต้องเข้าระบบหลังบ้านเลย

**จุดยืน (Positioning)**
**"หน้าร้านออนไลน์ที่สร้างและดูแลง่ายที่สุดสำหรับร้านไทย"**
ได้เว็บในไม่กี่นาที อัปเดตได้ในไม่กี่วินาทีผ่าน LINE และสวยตั้งแต่แรกด้วย template ที่ออกแบบมาสำหรับร้านไทย

**แกนหลัก 3 ข้อ**
1. **สร้างง่าย** ระบบถามคำถามเป็นภาษาไทย ไม่ต้องเขียน prompt
2. **ดูแลง่าย** อัปเดตเมนู ราคา เวลาเปิดปิด ประกาศ ผ่าน LINE
3. **ไทยจริง** มี LINE OA, PromptPay QR, Google Maps, ลิงก์ Shopee/Lazada ในตัว

## 2. ปัญหาและกลุ่มผู้ใช้

### กลุ่มผู้ใช้หลัก
| กลุ่ม | ตัวอย่าง | สิ่งที่ต้องการจากเว็บ |
|---|---|---|
| ร้านอาหาร / คาเฟ่ | ร้านกาแฟ, ร้านข้าว, ร้านขนม | เมนู ราคา แผนที่ เวลาเปิดปิด |
| ร้านบริการ | ร้านทำเล็บ, ร้านตัดผม, สปา, ช่างซ่อม | รายการบริการ จองคิวผ่าน LINE |
| แม่ค้าออนไลน์ | ขายเสื้อผ้า, ของทำมือ | แสดงสินค้า ลิงก์ไป Shopee/Lazada ชำระผ่าน PromptPay |
| ฟรีแลนซ์ / ติวเตอร์ | ช่างภาพ, ครูสอนพิเศษ | portfolio ราคา ช่องทางติดต่อ |

**ลักษณะร่วม:** ไม่มีความรู้เทคนิค, ไม่มีงบจ้างทำเว็บ, ใช้มือถือเป็นหลัก, ใช้ LINE ทุกวัน, มีเวลาน้อย

### ปัญหา
| # | ปัญหา | ผลที่เกิด |
|---|---|---|
| P1 | ไม่รู้จะเริ่มสร้างเว็บยังไง เครื่องมือที่มีใช้ศัพท์เทคนิค | ไม่มีเว็บเลย พึ่งแค่เพจ/marketplace |
| P2 | ไม่รู้ต้องบอก AI อะไรบ้างถึงจะได้เว็บที่ต้องการ | ได้เว็บที่ไม่ตรงกับร้าน |
| P3 | **สร้างเว็บแล้วไม่มีเวลาดูแล** ต้องเข้าระบบหลังบ้านบนคอม | ข้อมูลเก่า ราคาผิด เว็บร้าง ลูกค้าไม่เชื่อถือ |
| P4 | เว็บสำเร็จรูปไม่มีสิ่งที่ลูกค้าไทยใช้จริง | ต้องหาวิธีต่อ LINE/PromptPay เอง |

> **P3 คือปัญหาหลักที่โปรเจคนี้ให้น้ำหนักที่สุด** และต้องยืนยันด้วยการสัมภาษณ์ร้านจริง (ข้อ 13)

### Problem Statement (ร่างสำหรับ proposal)
> ธุรกิจขนาดเล็กในไทยจำนวนมากต้องการมีเว็บไซต์เพื่อสร้างความน่าเชื่อถือและให้ลูกค้าค้นหาเจอ แต่ขาดความรู้ทางเทคนิคและเวลาในการดูแล แม้ปัจจุบันจะมีเครื่องมือ AI ที่ช่วยสร้างเว็บไซต์ได้รวดเร็ว แต่ส่วนใหญ่เน้นการสร้างครั้งแรก ขณะที่การอัปเดตข้อมูลยังต้องเข้าระบบจัดการบนคอมพิวเตอร์ ทำให้เว็บไซต์ของร้านค้าจำนวนมากถูกทิ้งร้างและมีข้อมูลที่ไม่เป็นปัจจุบัน โครงการนี้จึงพัฒนาระบบผู้ช่วย AI ที่ให้ผู้ประกอบการสร้างและดูแลเว็บไซต์ได้ผ่านการสนทนาภาษาไทยบน LINE ซึ่งเป็นช่องทางที่ใช้อยู่ในชีวิตประจำวัน

### Pain → Solution
| ปัญหา | Solution |
|---|---|
| P1 เริ่มไม่เป็น | คุยกับ LINE OA ระบบถามทีละข้อ ได้เว็บทันที |
| P2 ไม่รู้จะบอก AI อะไร | ไม่ต้องเขียน prompt มีปุ่มให้เลือก ระบบสรุปแผนเว็บให้ยืนยันก่อนสร้าง |
| P3 ไม่มีเวลาดูแล | ส่งข้อความหรือรูปใน LINE แล้วเว็บอัปเดต แตะยืนยันครั้งเดียว |
| P4 ไม่มีของที่ร้านไทยใช้ | มี LINE OA, PromptPay QR, Maps, Shopee/Lazada ในตัว |

## 3. คู่แข่งและจุดต่าง

### คู่แข่งที่พบ
| กลุ่ม | ตัวอย่าง | เราเด่นกว่าตรงไหน |
|---|---|---|
| AI สร้างเว็บทั่วไป | Lovable, v0, Hostinger AI Builder, Kimi Websites, Figma Make | ออกแบบมาสำหรับร้านไทยโดยเฉพาะ · ดูแลต่อผ่าน LINE ได้ทันที |
| AI สร้างเว็บสำหรับ SME | Durable, GoDaddy Airo, Thryv | อัปเดตจาก LINE ได้เลย ไม่ต้องเปิดหน้าเว็บผู้ให้บริการ · มีของที่ร้านไทยใช้ครบ |
| แก้เว็บผ่านแชท | AI Site Biz (WhatsApp + อนุมัติก่อน), Eezix.ai, ChilledSites | ทำบน LINE ช่องทางหลักของร้านไทย · มี PromptPay, LINE OA และข้อมูลรายวัน |
| AI สร้างเว็บภาษาไทย | น้องใบบัว (Hosting Lotus), 60sec.site | อัปเดตผ่าน LINE · ข้อมูลรายวัน · ลูกจ้างช่วยอัปเดตได้ |
| แพลตฟอร์มร้านค้าไทย | LnwShop, Page365, LINE MyShop | ไม่ต้องตั้งค่าเอง AI สร้างให้จากการคุย |
| ทางเลือกฟรี | Facebook Page, Google Business Profile, LINE OA | เป็นเว็บของร้านเอง · รวมทุกอย่างไว้ลิงก์เดียว |

> เจ้าที่แก้เว็บผ่าน WhatsApp มีคนใช้จริงแล้ว เป็นหลักฐานว่าความต้องการนี้มีจริง · เรานำมาทำบน LINE ซึ่งเป็นช่องทางหลักของร้านไทย

### จุดต่างของเรา (จุดแข็งที่ชู)
1. **ดูแลเว็บผ่าน LINE** (จุดต่างหลัก) ส่งข้อความ/รูปเพื่ออัปเดตเว็บได้ทันที
2. **ไม่ต้องเขียน prompt** ระบบถามทีละข้อ มีปุ่มให้เลือก
3. **Component ร้านไทยครบ** LINE OA, PromptPay QR, Maps, Shopee/Lazada
4. **เสถียร ปลอดภัย** AI แก้แค่ข้อมูลผ่านคำสั่งที่ตรวจได้ ไม่แก้โค้ด และร้านยืนยันก่อนเผยแพร่ทุกครั้ง
5. **อัปเดตข้อมูลรายวันได้ทันที** "วันนี้ปิด" "ของหมด" "โปรถึงสิ้นเดือน" แสดงทันทีและหายเองเมื่อหมดเวลา
6. **ลูกจ้างช่วยอัปเดตได้** กดของหมด/ปิดวันนี้ได้ แต่แก้ราคาไม่ได้
7. **อัปเดตเล็กไม่คิดเงิน** เพราะอยากให้ร้านอัปเดตบ่อย (ข้อ 5)

## 5. Business Model

**หลัก**: อัปเดตเล็กฟรีไม่จำกัด · เครดิตเฉพาะงาน AI หนัก (สร้างเว็บใหม่ นำเข้าเมนูจากรูป ทำภาพโปร) · หาเงินจาก Pro และพันธมิตร

| แพ็กเกจ | สิ่งที่ได้ |
|---|---|
| ฟรี | 1 เว็บ, subdomain, ป้ายเล็กของระบบ, อัปเดตเล็กไม่จำกัด, เครดิตงานหนักจำนวนน้อย |
| Pro (รายเดือน) | โดเมนของตัวเอง, ไม่มีป้าย, สถิติผู้เข้าชม, บัญชีลูกจ้าง, เครดิตเพิ่ม |
| B2B2C | ธนาคาร ค่ายมือถือ หรือผู้ให้บริการชำระเงินมอบให้ลูกค้าร้านค้า (ตัวอย่างในไทย: AIS × BaseKit) |

**จุดขาย**: ดูแลง่ายผ่าน LINE ไม่ต้องจ้างคนดูแลเว็บ

**ต้นทุนต่อร้านต่อเดือน** = ค่า LLM (สร้าง + อัปเดต) + ค่าแพ็กเกจ LINE OA ÷ จำนวนร้าน + hosting
- LLM: สร้างเว็บ ~1 บาท · อัปเดต ~10 สตางค์ต่อครั้ง (ประมาณการ ต้องวัดจริง)
- LINE OA ของระบบใช้ร่วมทุกร้าน: แพ็กเกจฟรี push ได้ 300 ข้อความ/เดือน · Basic 1,280 บาท ได้ 15,000 · reply ไม่นับโควตา
- ระบบนับ token และต้นทุนทุกครั้ง เพื่อใช้ตัวเลขจริงในรายงาน

## 6. แนวคิดตัวผลิตภัณฑ์และ User Flow

### ช่องทาง
| ช่องทาง | ใช้ทำอะไร |
|---|---|
| **LINE OA ของระบบ** (หลัก) | คุยสร้างเว็บ, ส่งรูป, สั่งอัปเดต, รับแจ้งเตือน |
| **หน้าจัดการร้าน** (หน้าเดียวกัน เปิดใน LINE ผ่าน LIFF หรือบนคอมผ่าน LINE Login) | เลือกแบบ, ดูแผนและ preview, กดยืนยัน, ดูความคืบหน้า · บนคอมเหมาะกับ: แก้หลายรายการพร้อมกัน, อัปโหลดรูปหลายรูป, ประวัติเวอร์ชัน, สถิติ, ข้อมูลติดต่อ, ตั้งค่า |
| **เว็บไซต์ของร้าน** (ผลลัพธ์) | เว็บที่ลูกค้าของร้านเข้าดู + QR ติดหน้าร้าน |

### สร้างเว็บครั้งแรก (Pipeline ที่โค้ดกำหนดลำดับ ไม่ใช่ multi-agent อิสระ)
| ขั้น | หน้าที่ | Output |
|---|---|---|
| 1. รับงาน | ถามประเภทร้าน ชื่อ ที่ตั้ง (รูปโลโก้/เมนูถ้ามี) | Brief |
| 2. วางแผน | สรุป section ที่จะมี ให้ยืนยันใน LIFF | Plan |
| 3. ออกแบบ | เลือก template สี ฟอนต์ จากชุดที่ออกแบบไว้ | Site Settings |
| 4. เนื้อหา | เขียนคำโปรย เมนู คำอธิบายภาษาไทย | Shop Data |
| 5. ตรวจ | schema · กฎธุรกิจ · ลิงก์ · คำต้องห้าม (โค้ด) | ผ่าน / ส่งกลับ |
| 6. เผยแพร่ | บันทึกเวอร์ชัน เปิดเว็บ | ลิงก์ + QR |

```
ระบบ:  สวัสดีค่ะ ร้านของคุณขายอะไรคะ  [คาเฟ่] [ร้านอาหาร] [ร้านบริการ] [อื่นๆ]
ร้าน:  [คาเฟ่]
ระบบ:  ร้านชื่ออะไร อยู่แถวไหนคะ
ร้าน:  กาแฟดริปบางมด ตรงข้ามมอ
ระบบ:  ส่งรูปเมนูมาได้เลยค่ะ หรือกดข้ามก่อนก็ได้
ร้าน:  [ส่งรูปเมนู]
ระบบ:  อ่านได้ 8 รายการค่ะ นี่คือแผนเว็บ ช่วยเช็กหน่อยนะคะ [ดูแผน]
```

       • ลาเต้ 65 → 70 บาท
       • ครัวซองต์: หมด (วันนี้)
       [ยืนยัน] [แก้ไข] [ยกเลิก]

ระบบ:  อัปเดตเว็บเรียบร้อยค่ะ ✅ [ดูเว็บ]

- **กำกวม → ถามกลับ ไม่เดาเอง** เช่น มีลาเต้ร้อนกับเย็น ให้กดเลือก

### 8.4 อัปเดต: AI ออกคำสั่ง โค้ดเป็นคนแก้
AI **ไม่เขียน JSON Patch เอง** (path แบบ `/sections/1/items/-` เปราะ) แต่เลือกคำสั่งจากชุดที่กำหนด (function calling) แล้วโค้ดแปลงเป็นการแก้ข้อมูล

```json
{ "commands": [
    { "type": "update_item", "item_id": "i1", "changes": { "price": 70 } },
    { "type": "set_item_availability", "item_id": "i7", "available": false, "until": "end_of_day" }
  ],
  "needs_clarification": null }
```

| คำสั่ง | ตัวอย่าง | ลูกจ้างทำได้ |
|---|---|---|
| add_item / update_item / remove_item | "เพิ่มโกโก้เย็น 55" · "ลาเต้ขึ้นเป็น 70" | ❌ |
| set_item_availability | "ครัวซองต์หมดแล้ว" | ✅ |
| set_regular_hours | "เปลี่ยนเวลาเปิดเป็น 8 โมง" | ❌ |
| set_special_hours | "วันนี้ร้านปิด" · "พรุ่งนี้เปิด 10 โมง" | ✅ |
| add/remove_announcement | "โปรซื้อ 2 แถม 1 ถึงสิ้นเดือน" | ✅ |
| set_image · change_theme | ส่งรูป + "เปลี่ยนรูปหน้าร้าน" · "โทนเขียว" | ❌ |
| needs_clarification | ข้อความกำกวม → ส่งปุ่มให้เลือก | — |

ขั้นตอน: webhook → กันซ้ำ (`webhookEventId`) → ส่งรายการสินค้าพร้อม id ให้ AI → ได้คำสั่ง → **แปลงเวลา/ราคา/วันที่ไทยด้วยโค้ด** → ตรวจ schema · id มีจริง · กฎธุรกิจ · สิทธิ์ (ไม่ผ่าน AI ลองใหม่ 1 ครั้ง ไม่ผ่านอีก → ถามกลับ) → ส่งสรุป + ปุ่มยืนยัน → กดยืนยัน → บันทึกเวอร์ชัน + revalidate

**ตัวแปลงภาษาไทย** (มี unit test): "8 โมง"→08:00 · "บ่ายสอง"→14:00 · "สองทุ่มครึ่ง"→20:30 · "ตีหนึ่ง"→01:00 · "60บ."/"หกสิบ"/"๖๐"→60 · "พรุ่งนี้"/"จันทร์หน้า"/"สิ้นเดือน"→วันที่จริง

### 8.5 ข้อจำกัดของ LINE
- **reply token ใช้ได้ราว 1 นาที** · reply ไม่นับโควตา · push นับโควตา
- **ทางอัปเดตใช้ reply ล้วน**: ข้อความเข้า → reply สรุป + ปุ่ม · กดยืนยัน (postback ได้ token ใหม่) → reply ผล
- **push ใช้เฉพาะ** แจ้งเว็บเสร็จ · ชวนอัปเดต · สรุปสถิติ · ความคืบหน้าตอนสร้างเว็บดูใน LIFF
- webhook ต้องตอบเร็ว · LINE ส่งซ้ำได้ · รูปที่ผู้ใช้ส่งต้องดึงมาเก็บทันที

### 8.6 การแสดงผลเว็บร้าน
- Next.js ตัวเดียว route `/s/[shop]` cache ต่อร้าน · กดยืนยันแล้ว revalidate เฉพาะร้าน → เห็นผลในไม่กี่วินาที ไม่ต้อง build/deploy แยกร้าน
- สถานะ "เปิดอยู่/ปิดแล้ว" และประกาศหมดอายุคำนวณฝั่ง browser · มีงานล้างข้อมูลหมดอายุทุกคืน
- **สวย**: template ที่คนออกแบบ (AI ไม่เขียน CSS) · ชุดสีที่ตรวจ contrast แล้ว · ฟอนต์ไทย (Noto Sans Thai, IBM Plex Sans Thai, Prompt, Sarabun) ระยะบรรทัดพอสำหรับสระและวรรณยุกต์ · crop/บีบอัดรูปอัตโนมัติ
- subdomain ต้องมี wildcard DNS + cert ทำทีหลัง POC ใช้ path

### 8.7 Model และภาษา
| งาน | ตัวเลือกที่จะเทียบ |
|---|---|
| เขียนเนื้อหาไทยตอนสร้างเว็บ | DeepSeek Flash · Qwen Flash · Gemini 2.5 Flash-Lite · Typhoon |
| แปลงข้อความอัปเดตเป็นคำสั่ง | GLM-5.3-Flash · DeepSeek Flash · Gemini 2.5 Flash-Lite |
| อ่านรูปเมนู | GLM-OCR · typhoon-ocr · DeepSeek Flash (vision) |
| ช่วงพัฒนา | GLM ฟรี · model ฟรีบน OpenRouter |

- **ภาษา**: system prompt อังกฤษ · ข้อความผู้ใช้ไทยตามจริง · ชื่อคำสั่งและ JSON keys อังกฤษ · ค่าและเนื้อหาไทย · ไม่แปลไทย→อังกฤษ→ไทย (ชื่อเมนูและภาษาพูดเพี้ยน)
- **PDPA**: เบอร์ PromptPay, LINE ID, LINE user ID ไม่ส่งให้ AI ใช้ placeholder · ถ้าใช้ model จีน พิจารณา endpoint นอกจีน และระบุการส่งข้อมูลข้ามประเทศ
- **Router**: เลือก model ต่องานจาก config · fallback 1 ตัว · retry จำกัดรอบ · timeout · บันทึก token และต้นทุน
- ราคา model เปลี่ยนบ่อย เช็กหน้าทางการก่อนใช้ · ต้นทุน AI ต่ำมากไม่ใช่ตัวตัดสิน ตัวตัดสินคือความแม่นยำภาษาไทย

### 8.8 Golden Set (ทำตั้งแต่สัปดาห์แรก)
ใช้เป็นผล POC · เลือก model · regression test ทุกครั้งที่เปลี่ยน prompt/model
- ข้อความอัปเดต ~150 (ทุกคำสั่ง · หลายคำสั่งในข้อความเดียว · กำกวม · ภาษาพูด ตัวย่อ คำผิด เลขไทย)
- เวลา/ราคา/วันที่ ~100 · รูปเมนูจริง 20–30 · บทสนทนาสร้างเว็บ 20

## 13. สิ่งที่ต้องตรวจสอบต่อ

**สัมภาษณ์ร้าน 5 ร้าน** (ถามเรื่องที่เกิดขึ้นแล้ว ไม่เล่าไอเดียจนคุยจบ)
1. ลูกค้าใหม่ 3 คนล่าสุดรู้จักร้านจากไหน
2. เคยมีเว็บไหม ถ้ามี ทำไมเลิกอัปเดต ถ้าไม่มี ทำไม
3. ข้อมูลร้าน (เมนู ราคา เวลา) เปลี่ยนบ่อยแค่ไหน ครั้งล่าสุดแก้ที่ไหนบ้าง ใช้เวลาเท่าไร
4. ครั้งล่าสุดที่ปิดกะทันหันหรือของหมด แจ้งลูกค้ายังไง
5. เคยจ่ายเงินทำเว็บ ทำเพจ หรือโฆษณาไหม เท่าไร

**ผ่าน** ถ้าอย่างน้อย 3 ใน 5 ร้านเล่าปัญหาการดูแลข้อมูลเองโดยไม่ต้องชี้ และมี 1 ร้านยอมทดลอง
