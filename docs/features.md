**แม่แบบของแต่ละฟีเจอร์** — ใส่เฉพาะหัวข้อที่เกี่ยว: **ทำไม** (pain / เหตุผล) · **ใครทำอะไร** · **เปิด/ปิด** · **ใครเห็น** · **Plan** · **กติกา** · **ไม่ทำ** · **ข้อมูล** (ตารางใน `data-model.md`) · **Test**

**Checklist ตอนเพิ่มหรือตรวจฟีเจอร์** — ตอบได้ครบทุกข้อหรือยัง:
1. ใครทำได้ / ใครเห็นได้
2. เปิด–ปิดเมื่อไหร่ (สถานะงาน · เวลา)
3. อยู่ plan ไหน
4. ขัดกับฟีเจอร์อื่นหรือเอกสารอื่นไหม
5. มี Test (ปกติ + exception) หรือยัง

## กฎร่วมของทั้งระบบ

- **ห้ามเชื่อ client** — role check ต้องมีครบ 3 ทาง: REST · WebSocket message · **ตอนออก token / เปลี่ยนสิทธิ์ใน SFU**
- **User ไม่ผูกกับ role** — role อยู่ระดับงาน (`event_members.roles[]`) · คนเดียวกันเป็น Judge งานหนึ่งและ Visitor อีกงานได้
- **Admin = ผู้จัดงาน** role เดียว ทำได้ทุกอย่างในงาน · **มีได้หลายคน** (แนะนำ 2–3 คนแบบ Gather กันคนเดียวเข้าบัญชีไม่ได้แล้วงานค้าง) · **ต้องมีอย่างน้อย 1 คน** · คนสร้างงานเป็น Admin อัตโนมัติ
- **ลบงานต้องพิมพ์ชื่องานยืนยัน** · ที่เหลือใช้ dialog ยืนยันธรรมดา · ทุกการกระทำของ Admin ลง audit log
- **Admin คนสุดท้ายออกจากงานไม่ได้** (แบบ owner คนสุดท้ายของ GitHub org) → ปุ่มออกถูกปิด พร้อมข้อความ *"You're the only Admin. Add another Admin first, or delete the event."* · ลบบัญชีก็เช่นกัน: ถ้ายังเป็น Admin คนเดียวของงานไหน ต้องเพิ่ม Admin หรือลบงานนั้นก่อน
- **Module ต้องปิดได้** — `events.modules` (judging · popular vote · feedback · 3D · AI) · ปิดแล้ว UI และเมนูต้องหายทั้งหมด ไม่ใช่แค่ disable ปุ่ม
- **Plan limit บังคับที่ server** — `events.plan` · เกิน limit ต้องถูกปฏิเสธพร้อมข้อความบอกเหตุผล ไม่ใช่แค่ซ่อนปุ่ม
- **Ephemeral ให้ ephemeral จริง** — proximity chat, เสียง, reaction ไม่เก็บลง DB
- **ทุกกิจกรรมต้องเขียน analytics event** ไม่งั้นถือว่าเป็นของเล่น
- **Consent สองฝั่ง** — ไม่ใช่แค่ผู้จัดตั้งค่า ผู้เข้าร่วมเลือกเองว่าจะเปิดไมค์เมื่อไหร่ และเปิดเผยข้อมูลอะไร
- **Reuse ก่อนเสมอ** — ของที่ reuse บ่อยสุด: websocket broadcast, presence, analytics event, แมป Tiled, form builder

## ลำดับ Core / Cut

ถ้าไม่ทัน ตัดจากล่างขึ้นบน (ข้อ 1–5 ห้ามตัด)

1. ⭐ โลก 2D: เดินในฮอลล์ + บูธ + proximity voice/text + mute/kick/ban
2. ⭐ หน้าบูธ + poster viewer + เสียงโซนบูธ + แชร์จอ

6. import ผลงานจาก CSV/XLSX · Admin panel ในฮอลล์ (ส่วนอื่นนอกจาก mute/kick/ban) · Exhibition หลังงาน

## User Flow

**แนวคิด** — แยก 3 เรื่องไม่ปนกัน: **บัญชี** (login + onboarding ครั้งเดียว ใช้ได้ทุกงาน) · **role ในงาน** (Admin / Presenter / Judge ได้จากคำเชิญ) · **การเข้างาน** (กด Interested ก่อนงานได้ · ทุก role กรอกฟอร์มเข้างานตอนเข้าครั้งแรก)

**A. Admin**
1. login → Create event (Draft): ข้อมูลงาน · เวลาเริ่ม (ทันที / ตั้งเวลา) + เวลาจบ (บังคับ · ค่าเริ่มต้น 23:59) · จำกัดโดเมน (ไม่บังคับ) · module · เลือกฮอลล์ preset + จำนวนคนพร้อมกัน
2. เพิ่มผลงาน: manual · CSV/XLSX · ฟอร์มให้ Presenter ส่งเอง · AI import — ข้อมูลแค่โครง (ชื่อ · หมวด · อีเมลสมาชิก) Presenter กรอกรายละเอียดเอง
3. ใส่อีเมล Judge + สร้าง rubric · ตั้งคำถามในฟอร์มเข้างาน / survey หลังงาน (ไม่บังคับ)
4. Admin กด Publish → ระบบส่งคำเชิญ · หน้างานเปิดให้กด Interested
5. วันงาน: ฮอลล์เปิดตามเวลาหรือกดเปิดเอง → ดูแลผ่าน Admin panel ในฮอลล์ · assign role ระหว่างงานได้ (เช่น สร้างบูธเปล่าแล้วให้ Visitor เป็น Presenter)
6. จบงาน (Admin กด หรือถึงเวลาจบ) → judging + Popular Vote ปิด · งานเข้า Exhibition → Admin ประกาศผล → analytics

**B. Presenter**
1. ได้อีเมลเชิญ → กดลิงก์ → login (+ onboarding ถ้าครั้งแรก) → รับคำเชิญ
2. ไปหน้าบูธของตัวเองทันที → กรอกรายละเอียด + อัปไฟล์ตาม checklist · เชิญเพื่อนร่วมทีมเข้าบูธได้ · เปิด AI assistant ได้ (ถ้าผู้จัดเปิด module)
3. วันงาน: เข้าฮอลล์ → บูธตัวเอง → พูด/แชร์จอให้คนในบูธ · แก้บูธระหว่างงานได้
4. หลังงาน: ดูสถิติ · feedback · คะแนน (หลังประกาศผล)

**C. Judge**
1. ได้อีเมลเชิญ → กดลิงก์ → login → รับคำเชิญ → เห็น rubric + รายการผลงานที่ได้รับมอบหมาย
2. วันงาน: เดินไปบูธ ฟังนำเสนอ → ให้คะแนนในแผงบูธ (หรือจากหน้ารายการผลงาน) · แก้ได้จนกว่างานจบ

**D. Visitor** — เข้าจากหน้า Explore หรือลิงก์ที่ผู้จัดแชร์ → ก่อนงานกด `Interested` (login + onboarding ถ้ายังไม่มี) → ฮอลล์เปิดได้ noti ในแอป / ปฏิทินเตือน → `Join` → ฟอร์มเข้างาน (ครั้งแรก) → ฮอลล์

**E. Visitor งานจำกัดโดเมน** — เหมือน D แต่ต้อง login ด้วยอีเมลโดเมนที่ผู้จัดกำหนด (เช่น @kmutt.ac.th) · อีเมลอื่นเห็นงานแต่เข้าไม่ได้

**F. งานเริ่มแล้ว** — ไม่ต้องกด Interested ก่อน · `Join` → login → ฟอร์มเข้างาน → ฮอลล์ · ฮอลล์เต็ม → `Hall is full` (เฉพาะ Visitor)

**G. มือถือ** — ใช้ฮอลล์เดียวกันแบบ responsive: แตะเพื่อเดิน · แผงบูธเป็น bottom sheet

**H. หลังงาน (Exhibition)** — ฮอลล์ยังเดินชมได้ เป็นพื้นที่โชว์ผลงาน · ดูวัสดุในบูธ · ถาม AI assistant · ฝาก feedback ต่อได้

## 1. Account & Platform

### Auth ⭐ M
- **ทำไม**: ไม่มี guest — guest ทำให้ ban ไม่ได้ผล · analytics เพี้ยน · กรรมการ/ผู้นำเสนอยืนยันตัวไม่ได้ · proximity voice ทำให้คนก่อกวนพูดใส่คนอื่นได้ทันที
- **ใครทำอะไร**: login ด้วย Microsoft (บัญชีองค์กร เช่น @kmutt.ac.th + บัญชีส่วนตัว) · Google · magic link (ทางสำรอง · ปุ่ม Google/Microsoft อยู่บน)
- **ใครเห็น**: หน้างาน (ข้อมูลงาน + รายการผลงาน) **ดูได้โดยไม่ login** · ต้อง login เมื่อกด Interested · เข้าฮอลล์ · ฝาก feedback · โหวต
- **กติกา**: Google + Microsoft อีเมลเดียวกัน = บัญชีเดียว (account linking) · ⚠️ **JWT ห้ามฝัง event role** — role เปลี่ยนระหว่างงานได้ ต้องเช็คจาก DB/cache ทุกครั้ง
- **ข้อมูล**: `users` · `sessions` · `accounts` · `verifications` · `jwks`

### Onboarding ครั้งแรก M
- **ใครทำอะไร**: บังคับครั้งเดียวหลัง login ครั้งแรก (~30 วินาที) → เสร็จแล้ว**กลับไปหน้าที่ตั้งใจไป** (หน้างาน / หน้ารับคำเชิญ)
- **กติกา**: บังคับ: ชื่อที่แสดง (เติมจาก OAuth) · preset avatar · ประเภทผู้ใช้ (นักศึกษา · นักเรียน · บริษัท · ศิษย์เก่า · ผู้ปกครอง · อาจารย์) · จังหวัด (วัด SDG) · ไม่บังคับ: องค์กร/คณะ · ตำแหน่ง/ชั้นปี · ทุกช่องต้องบอกว่าเอาไปใช้ทำอะไร
- **ข้อมูล**: `users` (ช่อง profile · `onboarded_at`)

### คำเชิญ (Invite) ⭐ M
- **ทำไม**: role ที่มีสิทธิ์พิเศษต้องพิสูจน์ตัว · กดลิงก์ได้ = เข้าถึงกล่องอีเมลนั้น
- **ใครทำอะไร**: Admin เชิญ Admin/Presenter/Judge · Presenter เชิญสมาชิกเข้าบูธตัวเอง · ส่งทางอีเมลเป็นลิงก์ที่มี token
- **ใครเห็น**: ถ้าอีเมลที่เชิญมีบัญชีอยู่แล้ว คำเชิญขึ้นในหน้า Home ด้วย · ฝั่ง Admin เห็นแค่ `pending` จนกว่าจะรับ (ไม่เปิดเผยว่าอีเมลไหนมีบัญชี) · หลังรับ Admin เห็นว่ารับด้วยบัญชีไหน และถอด role ได้
- **กติกา**:
    - อีเมลของบัญชีตรงกับคำเชิญ → รับได้ทันที · ไม่ตรง → แสดง *"This invite is for k\*\*\*@kmutt.ac.th · You're signed in as x@gmail.com"* + `Switch account` / `Accept with this account`
    - รับด้วยบัญชีอื่น → ระบบจำอีเมลที่ถูกเชิญไว้กับบัญชีนั้น · คำเชิญครั้งต่อไปที่อีเมลนี้จับคู่อัตโนมัติ
    - token ใช้ได้ครั้งเดียว · หมดอายุ 14 วัน · Admin กด resend (token เก่าใช้ไม่ได้) / ยกเลิกได้
    - คำเชิญทุกใบ (pending + รับแล้ว) **จองที่ในฮอลล์** · เชิญเกิน capacity → ปฏิเสธพร้อมให้อัปเกรด
    - จำกัดจำนวนคำเชิญต่อวันต่องาน (กันใช้ระบบส่งอีเมลสแปม) · อีเมลระบุชื่อคนเชิญและชื่องาน · ลง audit log
- **ข้อมูล**: `event_invites` · `user_emails`
- **Test**: บัญชีที่สองกดลิงก์ที่ถูกรับแล้วต้องถูกปฏิเสธ · token หมดอายุ / ถูกยกเลิก · resend แล้วลิงก์เก่าต้องใช้ไม่ได้ · Presenter/Judge เชิญ Admin ต้องถูกปฏิเสธ · เชิญเกิน capacity ต้องถูกปฏิเสธที่ server

### App role M
- `USER` / `PLATFORM_ADMIN` · แยกคนละแกนกับ event role · ⚠️ **Platform Admin** = ทีมเราที่ดูแลทั้งระบบ · **Admin** = ผู้ดูแลงานแต่ละงาน · เขียนเต็มเสมอ ห้ามย่อปนกัน · **ข้อมูล**: `users.app_role`

### Edit Profile M

- **กติกา**: ⚠️ PDPA: ฟอร์มเข้างานแจ้งว่าคนในงานจะเห็นอะไร · ไม่ต้องขอ consent แยก (องค์กร/ตำแหน่งไม่บังคับ ไม่อยากให้เห็นก็เว้นว่าง)
- **ข้อมูล**: `users`

## 2. Event Setup

### Event CRUD ⭐ M
- **ใครทำอะไร**: คนสร้างงานเป็น **Admin** อัตโนมัติ · เพิ่ม Admin ได้หลายคน
- **กติกา**: ข้อมูลงาน: ชื่อ · คำอธิบาย · cover · หมวดผลงาน (ไม่บังคับ · ใช้กรอง + จัดโซน) · agenda (แสดงให้ผู้ชมรู้ · ไม่ล็อกอะไร) · **Module toggle**: judging · popular vote · feedback · 3D · AI
- **ข้อมูล**: `events` · `event_categories` · `event_members`

### สถานะและเวลาของงาน ⭐ M
- **กติกา**:
    - `Draft → Published → Live → Exhibition → Archived` · Draft: ตั้งค่า คนอื่นไม่เห็น · Published: หน้างานเปิด กด Interested ได้ · Live: ฮอลล์เปิด · Exhibition: หลังงาน เดินชมได้ judging ปิด · Archived: ปิดฮอลล์
    - **เวลาเริ่ม**: ทันที หรือตั้งเวลา (Admin เปิดก่อนได้)
    - **เวลาจบบังคับ** (ค่าเริ่มต้น 23:59 ของวันเริ่ม) · Admin ขยายระหว่างงานหรือกดจบก่อนได้ · **ถึงเวลาระบบจบงานเอง** (กันลืมปิด) · เตือน Admin 30 นาทีก่อนจบ
    - **จบงาน = ปิดรอบ judging + Popular Vote พร้อมกัน** → เข้า Exhibition · Admin กดประกาศผลเมื่อพร้อม

## 4. Inside the Virtual Event

### 4.1 Roles (ระดับ event · 1 คนมีได้หลาย role)

| Role | จำนวน | ทำอะไรได้ |
|---|---|---|
| `ADMIN` | ≥ 1 คน | ผู้จัดงาน ทำได้ทุกอย่างในงาน — ตั้งค่า · เผยแพร่ · เปิดฮอลล์ · จบงาน · ประกาศผล · assign role · moderation (รวม mute ในบูธ) · ดู analytics · ในฮอลล์เหมือนผู้ชมที่มีสิทธิ์ moderation · **ไม่แชร์จอ/เปิดกล้อง** เว้นแต่ assign ตัวเองเป็น Presenter ของบูธนั้นด้วย |
| `PRESENTER` | หลายคน | จัดการบูธของตัวเอง (ก่อนและระหว่างงาน) · เชิญสมาชิกเข้าบูธตัวเอง · แชร์จอ + mute คนในบูธ **เฉพาะในบูธตัวเอง** · เห็น feedback + สถิติ **ของบูธตัวเอง** · เห็นคะแนนกรรมการ**หลังประกาศผล** |
| `JUDGE` | หลายคน | ให้คะแนนผลงานที่ได้รับมอบหมาย · เห็นเฉพาะคะแนนของตัวเอง · แก้ได้จนกว่างานจบ |
| `VISITOR` | — | ค่าเริ่มต้นของทุกคนที่เข้างาน (ไม่มีแถวใน `event_members`) |

- ในเอกสารนี้ "ผู้จัด" = Admin
- ทุก role ต้อง login · **สิทธิ์ = union ของทุก role** ไม่ใช่ hierarchy
- **Role badge บนแมป** — `Admin` · `Presenter` · `Judge` เห็นชัดทั้งบนตัวละครและในรายชื่อ · Visitor ไม่มี badge · มีหลาย role = แสดงหลาย badge · ⚠️ **ต้องออกจากฝั่ง server** (กันปลอมเป็นกรรมการ/ผู้นำเสนอ)

- **ข้อมูล**: `projects` (full-text) · `analytics_events` type `search`

### 4.4 Booth ⭐

#### โครงสร้างและภายนอกบูธ
- **กติกา**: 1 บูธ = 1 ผลงาน · หลายผู้นำเสนอ (สมาชิกทีม) · ผู้นำเสนอแต่งเอง · งาน hybrid ทีมแบ่งกันเองว่าใครอยู่ออนไลน์
- **ใครเห็น**: เดินเฉียดเห็น cover + ชื่อผลงาน + หมวด + ป้าย `● Live` (มี Presenter ≥ 1 คนในบูธ · ไม่มีก็ไม่แสดงป้าย) + จำนวนคนในบูธ `👥 12` (แก้ "ไม่กล้าเข้า" — เห็นก่อนว่ามีทีมให้คุยและมีคนอยู่) · ช่วง Exhibition แสดงแค่จำนวนคน

#### ข้อมูลบูธ M
- **ใครทำอะไร**: Presenter ใส่ ชื่อ · summary · หมวด · tags · cover/thumbnail · สมาชิกทีม · โปสเตอร์ · สไลด์ · วิดีโอ (ฝัง YouTube/Vimeo **ไม่โฮสต์เอง**) · ลิงก์อื่น · ไฟล์ให้ AI อ่าน (รายงาน · README)
- **กติกา**: หน้าแก้บูธมี checklist ว่ายังขาดอะไร + deadline ที่ผู้จัดตั้ง (เป็นแค่การเตือน ไม่ล็อก เพราะแก้บูธระหว่างงานได้)
- **ข้อมูล**: `projects` · `project_files` · `events.booth_deadline`

#### แก้บูธระหว่างงาน M
- แก้ได้ทั้งหน้าบูธของตัวเอง (dashboard) และปุ่ม Edit ในแผงบูธในฮอลล์ (React overlay) · ใช้ API เดียวกัน · broadcast ให้คนในบูธเห็นทันที · ลง `audit_logs`

#### Poster viewer ⭐ M
- **ทำไม**: แก้ "โปสเตอร์อ่านยาก ต้องเปิดแยก" ของ Gather
- **กติกา**: โปสเตอร์ PDF แปลงเป็นรูปตอนอัปโหลด · ซูม/เลื่อนได้ · **ผู้นำเสนอชี้/ซูม แล้วจอผู้ชมในบูธตามไปด้วย** · ตรวจไฟล์ + preview ตอนอัปโหลด
- **ข้อมูล**: `project_files` kind `POSTER` · `analytics_events` type `poster_view`

#### แชร์จอในบูธ ⭐ 🔊 M
- **ใครทำอะไร**: แชร์ได้เฉพาะ Presenter ของบูธนั้น (เดโมแอป/สไลด์)
- **ใครเห็น**: เฉพาะคนในโซนบูธ · เดินออกจากบูธแล้วหาย
- **กติกา**: **แชร์ได้ทีละ 1 จอต่อบูธ** · ถ้ามีคนกดแชร์ระหว่างที่อีกคนแชร์อยู่ จอใหม่จะแทนจอเดิม (แบบ Zoom/Teams) · simulcast ให้เน็ตช้าได้ภาพความละเอียดต่ำ
- **ข้อมูล**: `analytics_events` type `screen_share_start` / `screen_share_end`
- **Test**: Presenter คนที่ 2 กดแชร์ระหว่างอีกคนแชร์อยู่ต้องแทนจอเดิม · Visitor กดแชร์ต้องถูกปฏิเสธ · ผู้ชมเน็ตช้าดูจอแชร์

#### กล้องผู้นำเสนอ 🔊 S
- ผู้นำเสนอเปิดเองได้ ไม่บังคับ · เห็นเฉพาะคนในโซนบูธ · **ไม่ทำ**: กล้องของผู้ชม

#### Shared 3D viewer C
- ผู้นำเสนอเปิดโมเดล `.glb` หมุน/ซูม แล้วผู้ชมในบูธเห็นตาม (เหมือนถือชิ้นงานจริงให้ดู) · `<model-viewer>` · **ข้อมูล**: `project_files` kind `MODEL_3D`

#### ไฟล์อัปโหลด
- เก็บที่ MinIO ไม่ใช่ใน DB · ⚠️ **ตรวจ MIME type จริงที่ server ไม่เชื่อนามสกุล** · จำกัดขนาด · serve ผ่าน signed URL ที่หมดอายุ · path อยู่ใน `data-model.md`

- **Test (บูธ)**: ผู้นำเสนอเน็ตหลุดตอนนำเสนอ · ผู้นำเสนอถูกถอด role ตอนอยู่ในบูธ · อัปโหลดไฟล์เปลี่ยนนามสกุล · โปสเตอร์ไฟล์ใหญ่มาก · แก้บูธขณะมีคนดูอยู่

### 4.5 Communication

#### Proximity voice chat ⭐ 🔊 M
- **กติกา**: ดังตามระยะห่าง · **ระยะเท่า Gather**: เริ่มได้ยินที่ 5 ช่อง · เสียงเต็มภายใน 2 ช่อง แล้วเบาลงตามระยะ · hysteresis ตัดเสียงที่ 7 ช่อง (กันกะพริบที่ขอบ · ยืนยันใน S4) · จอแชร์และกล้องผู้นำเสนอไม่ใช้ระยะ ใช้โซนบูธ · ⚠️ **ต้องใช้ SFU** เพราะการเปลี่ยนคนที่ได้ยินต้องเป็นการเปลี่ยน subscription ไม่ใช่สร้าง connection ใหม่

#### Proximity text chat ⭐ M
- **ทำไม**: สำหรับคนที่เปิดไมค์ไม่ได้
- **กติกา**: แบบ Nearby chat ของ Gather: ลอยเหนือหัวสั้นๆ (~5 วิ · Gather ไม่ระบุตัวเลข) + หน้าต่าง Nearby chat เล็กๆ ที่ข้อความหายไปเอง · ไม่เก็บลง DB

#### เสียงโซนบูธ ⭐ 🔊 M (spike S5)
- **ทำไม**: pain 1 — บูธคนเกิน 4–5 คนคุยไม่รู้เรื่อง (NeurIPS ต้องย้ายไป Zoom)
- **กติกา**:
    - ไม่มีโหมดนำเสนอหรือส่งไมค์ · ใครอยากพูดก็พูด (แบบ Zoom/Teams)
    - ทุกคนที่อยู่**ในโซนบูธได้ยินกันชัดเท่ากัน** (เหมือนห้องเดียว ไม่ลดตามระยะ)
    - **เสียงไม่ทะลุทั้งสองทาง** (แบบ private area ของ Gather) — คนในบูธไม่ได้ยินเสียงนอกบูธ (กันเสียงคนคุยเรื่องอื่นหลุดเข้ามา) · คนนอกบูธไม่ได้ยินในบูธ · บอกคนข้างนอกด้วยภาพแทน: ป้าย `● Live` · จำนวนคน · avatar ในบูธ · วงรอบ avatar ของคนที่กำลังพูด
    - **Presenter ของบูธนั้น + Admin กด mute คนในบูธได้** (แบบ host ใน Zoom) · คนที่ถูก mute เปิดไมค์เองได้ · **ไม่มีใครเปิดไมค์ให้คนอื่นได้** (แนวเดียวกับ Zoom ที่เลิก unmute โดยไม่ถาม) · ⚠️ mute ที่ server ไม่ใช่แค่ฝั่ง client
- **Test**: Presenter mute คนในบูธอื่นต้องถูกปฏิเสธ · Visitor mute คนอื่นต้องถูกปฏิเสธ · เดินเข้า/ออกขอบโซนบูธเสียงต้องไม่กะพริบ · บูธมี 15+ คนเปิดไมค์พร้อมกัน · บูธมี 50 คน (ไม่มีคิว จึงต้องรับได้)

#### ไมค์ปิดเป็นค่าเริ่มต้น S
- เข้างานแล้วฟังได้อย่างเดียวจนกว่าจะเปิดเอง · ลดจำนวน track เสียงในบูธที่คนเยอะด้วย

#### Public event chat S
- แผงข้าง ทุกคนในงานเห็น · เก็บใน memory เฉพาะช่วงงาน · ประกาศจากผู้จัด

#### Reaction / emote C
- 👏 ❤️ 😂 ❓ 🔥 · rate limit ~3 ครั้ง/วินาที · **ไม่ทำ**: reaction เชิงลบ

#### ไม่ทำ
- **Direct Message** — ตัดโดยเจตนา การตามต่อหลังงานใช้ "ขอให้ติดต่อกลับ"
- **ข้อแลกเปลี่ยนที่ยอมรับ** — ไม่เก็บ chat = report ย้อนหลังไม่ได้ (report ระหว่างงานคัดลอกข้อความไว้) แลกกับการไม่ต้องแบกภาระ PDPA ของข้อความ

### 4.6 Judging ⭐ M 💰
- **ทำไม**: pain 5 — ให้คะแนนด้วยกระดาษ/spreadsheet คีย์ซ้ำ รวมช้า
- **ใครทำอะไร**:
    - กรรมการเห็น **รายการผลงานที่ได้รับมอบหมาย + สถานะ** (ยังไม่ให้ · ให้แล้ว) + ปุ่มไปบูธ
    - เดินไปบูธ ฟังนำเสนอ ถามสด → **เปิดแผง rubric ในบูธ** ให้คะแนนรายเกณฑ์ + comment · ให้/แก้คะแนนจากหน้ารายการผลงานได้ด้วย (API เดียวกัน)
    - ผู้จัดเห็น**ความคืบหน้า** (กรรมการคนไหนยังให้ไม่ครบ) · เตือนกรรมการได้
- **เปิด/ปิด**: ให้คะแนนได้ตอน Live · **ปิดเมื่องานจบ** · Admin กดประกาศผลหลังจบงาน
- **ใครเห็น**: กรรมการเห็นเฉพาะคะแนนของตัวเอง · ⚠️ ผู้นำเสนอ/ผู้ชม **ห้ามเห็นคะแนนก่อนประกาศ** (ตรวจที่ server) · หลังประกาศ **หน้างานแสดงเฉพาะผู้ชนะ** (judging + Audience award) · คะแนนละเอียดเห็นแค่เจ้าของผลงาน + Admin · comment กรรมการส่งให้ผู้นำเสนอ (ผู้จัดซ่อนได้ก่อนส่ง)
- **กติกา**:
    - คะแนน autosave ทุกครั้งที่แก้ (สถานะ draft) → กด Submit เมื่อให้ครบ · แก้ได้จนกว่างานจบ
    - **ตอนงานจบ**: draft ที่ให้ครบทุกเกณฑ์ = นับเป็นส่ง (กันลืมกด Submit) · **ไม่ครบไม่นับ** (คะแนนครึ่งๆ ทำให้ผลรวมเพี้ยน) · ผลงานนั้นเฉลี่ยจากกรรมการที่ให้ครบ · ผู้จัดเห็นผลงานที่คะแนนไม่ครบ · เตือนกรรมการที่ยังไม่ครบ 30 นาทีก่อนจบ
    - ผลรวมถ่วงน้ำหนักอัตโนมัติ (สูตรใน `data-model.md`)
- **ไม่ทำ**: normalize คะแนนต่อกรรมการ
- **ข้อมูล**: `score_sheets` · `scores` · `awards`
- **Test**: กรรมการให้คะแนนผลงานที่ไม่ได้รับมอบหมาย · แก้คะแนนหลังงานจบ · draft ไม่ครบต้องไม่ถูกนับ · ลบเกณฑ์ที่มีคะแนนแล้ว · กรรมการ 2 แท็บให้คะแนนพร้อมกัน

### 4.7 Feedback · Popular Vote

#### Feedback M
- **ทำไม**: pain 2 — feedback น้อย
- **ใครทำอะไร**: ผู้ชมฝากข้อความถึงผลงาน · ผู้นำเสนอกดซ่อนได้ · Admin ลบได้
- **เปิด/ปิด**: ตอน Live และ Exhibition
- **ใครเห็น**: **เห็นแค่ผู้นำเสนอของบูธ + Admin ไม่แสดงสาธารณะ** · เลือกไม่ระบุชื่อได้ = ผู้นำเสนอไม่เห็นชื่อ แต่ Admin เห็น
- **ข้อมูล**: `feedbacks`

#### Popular Vote S
- **ใครทำอะไร**: ผู้ชมโหวตได้ไม่จำกัดจำนวนผลงาน แต่**ผลงานละ 1 ครั้ง** ถอนได้ (แบบ Hack the North)
- **เปิด/ปิด**: ตอน Live · **ปิดเมื่องานจบ** และประกาศผลพร้อม judging
- **ใครเห็น**: ผลแสดงเป็น Audience award หลังประกาศ
- **Plan**: ใช้ได้ทั้ง Free และ Pro
- **กติกา**: ต้องแวะบูธก่อนโหวตได้ (กันโหวตโดยไม่ดู — ตั้งค่าได้)
- **ไม่ทำ**: rubric ของผู้ชม (อยากให้ใครให้คะแนนตามเกณฑ์ → เชิญเป็น Judge)
- **ข้อมูล**: `votes` (PK กันโหวตซ้ำ) · `booth_visits`
- **Test**: โหวตซ้ำต้องถูกปฏิเสธ · โหวตหลังงานจบต้องถูกปฏิเสธ · ยังไม่แวะบูธโหวตไม่ได้ (เมื่อเปิดเงื่อนไข)

### 4.8 Admin panel & Moderation

#### Admin panel ในฮอลล์ M
- overlay สำหรับเรื่องที่ต้องทำทันที: จำนวนคน · สถานะบูธ · report · Announce · mute/kick/ban · สวิตช์ฉุกเฉิน · คลิก avatar แล้ว assign role · งานตั้งค่า · analytics · ผลคะแนน อยู่ใน dashboard ด้านนอก (เปิดแท็บใหม่จากในฮอลล์ได้)

#### mute / kick / ban ⭐ M (ตัดไม่ได้)
- **ใครทำอะไร**: ADMIN
- **กติกา**: **kick** = ดีดออกจากฮอลล์ กลับเข้าได้ทันที (เตือน) · **ban** = blacklist ของงานนี้ ผูก user_id ตัด session ทันที เข้างานนี้ไม่ได้อีกจนกว่า Admin ยกเลิก (งานอื่นเข้าได้ปกติ) · ban ได้ผลจริงเพราะบังคับ login
- **ข้อมูล**: `event_bans` · `audit_logs`

#### Report และสวิตช์ฉุกเฉิน M
- **report** — ผู้ใช้กด report คนหรือข้อความได้ → queue ให้ Admin ตรวจ · ลบข้อความและ feedback ที่ไม่เหมาะสม
- **audit log ทุกการกระทำ** — ใครทำอะไรกับใคร เมื่อไหร่ เพราะอะไร
- **สวิตช์ฉุกเฉิน** — ปิดรับคนเข้าใหม่ / ปิดไมค์ทั้งงาน
- **ข้อมูล**: `reports` · `audit_logs`

### 4.9 ขอให้ติดต่อกลับ S
- **ใครทำอะไร**: ผู้ชมที่สนใจผลงาน (เช่น บริษัทที่อยากรับฝึกงาน) กดปุ่มในบูธเพื่อฝากช่องทางติดต่อให้ทีม · กรอก: อีเมล (เติมจากบัญชี แก้ได้) · เบอร์/LinkedIn/ข้อความสั้น (ไม่บังคับ) — ไม่เก็บใน profile · ผู้ชมถอนได้
- **เปิด/ปิด**: ตอน Live และ Exhibition
- **ใครเห็น**: ผู้นำเสนอของบูธนั้นเห็นรายชื่อในสรุปบูธ + export CSV
- **กติกา**: **ทางเดียว** ไม่มีการแลก contact ระหว่างผู้ชมด้วยกัน · ⚠️ ต้องมีข้อความข้างปุ่มว่า *"ทีมจะเห็นชื่อ องค์กร และข้อมูลที่คุณกรอก"* (PDPA) · ห้ามใช้คำว่า "สนใจ" ที่กำกวม
- **ข้อมูล**: `contact_requests`
- **Test**: ผู้นำเสนอบูธอื่นเห็นรายชื่อของบูธนี้ต้องถูกปฏิเสธ · ถอนแล้วทีมต้องไม่เห็นอีก

## 5. Post-Event

### Exhibition S
- **ทำไม**: pain 8 — งานจบแล้วผลงานหายไป
- **ใครทำอะไร**: หลังงานฮอลล์ยังเดินชมได้ เป็น**พื้นที่โชว์ผลงาน** · ยังเป็น multiplayer (คนที่เข้ามาพร้อมกันคุยกันตามระยะได้) · ดูวัสดุในบูธ · AI assistant ตอบแทน · ฝาก feedback ได้
- **เปิด/ปิด**: เริ่มเมื่องานจบ · Free 7 วัน · Pro 30 วัน (นานกว่านี้ซื้อ Event add-on) → หมดแล้วเข้า Archived · Admin ปิดก่อนได้
- **กติกา**: judging และ Popular Vote ปิด · ไม่มีการนัดหรือแสดงว่าผู้นำเสนอจะกลับมาเมื่อไหร่ · ฮอลล์ที่ไม่มีคนไม่กินทรัพยากร server (room ถูกทิ้งเมื่อว่าง) · ต้นทุนที่เหลือคือ storage
- **ข้อมูล**: `events.exhibition_until`

### Analytics สำหรับผู้จัด ⭐ M
- **ทำไม**: pain 6 · *จุดขายหลัก*
- **ใครเห็น**: Admin

### 6.2 AI Features 🤖 💰 (Pro)

#### AI ผู้ช่วยตอบเรื่องผลงาน (RAG) S
- **ใครทำอะไร**: ผู้นำเสนออัปโหลดเอกสาร (โปสเตอร์ · รายงาน · สไลด์) → chunking + embedding เก็บใน **pgvector** → ตอบคำถามผู้ชมตอน**ผู้นำเสนอไม่อยู่ในบูธ** และใน **Exhibition** · ใช้ไฟล์ชุดเดียวกับในบูธ ไม่ต้องอัปโหลดซ้ำ
- **เปิด/ปิด**: เปิด 2 ชั้น: ผู้จัดเปิด module ระดับงาน → ผู้นำเสนอเปิดของบูธตัวเอง · ผู้นำเสนอ**ลองถามก่อนเปิดใช้จริง**
- **กติกา**: ⚠️ ต้องมี **guardrail** — ตอบเฉพาะจากเอกสารผลงาน ถ้าไม่รู้ต้องบอกว่าไม่รู้ · แสดงว่าเป็นคำตอบจาก AI ไม่ใช่ผู้นำเสนอ · AI ตอบไม่ได้ → แนะนำให้ฝาก feedback หรือกด "ขอให้ติดต่อกลับ" · จัดเป็น Intermediate–Advance ได้เพราะมี retrieval pipeline ของตัวเอง ไม่ใช่ prompt เปล่า
- **ข้อมูล**: `projects.ai_enabled` · `project_files.use_for_ai` · `doc_chunks` · `analytics_events` type `ai_question`

#### AI สรุป feedback S
- รวม feedback ผู้ชม + comment กรรมการ → สรุปจุดแข็ง/จุดที่ควรปรับให้ผู้นำเสนอ (แก้ pain "feedback เยอะแต่เอาไปใช้ยาก / feedback น้อย")

#### AI import ผลงาน S
- ดู §2 ผลงานและบูธ · คนตรวจก่อนบันทึกเสมอ

- ต้องวัด **ต้นทุนต่องาน** ของ AI เพราะเข้าไปอยู่ในโครงสร้างต้นทุนของ business model
