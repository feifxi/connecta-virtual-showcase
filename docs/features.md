## กฎร่วมของทั้งระบบ

- **ห้ามเชื่อ client** — role check ต้องมีครบ 3 ทาง: REST · WebSocket message · **ตอนออก token / เปลี่ยนสิทธิ์ใน SFU**
- **User ไม่ผูกกับ role** — role อยู่ระดับงาน (`event_members.roles[]`) · คนเดียวกันเป็น Judge งานหนึ่งและ Visitor อีกงานได้
- **Module ต้องปิดได้** — `events.modules jsonb` (judging · popular vote · feedback · 3D · AI) · ปิดแล้ว UI และเมนูต้องหายทั้งหมด ไม่ใช่แค่ disable ปุ่ม
- **Plan limit บังคับที่ server** — `events.plan` · เกิน limit ต้องถูกปฏิเสธพร้อมข้อความบอกเหตุผล ไม่ใช่แค่ซ่อนปุ่ม
- **Ephemeral ให้ ephemeral จริง** — proximity chat, เสียง, reaction ไม่เก็บลง DB
- **ทุกกิจกรรมต้องเขียน analytics event** ไม่งั้นถือว่าเป็นของเล่น
- **Consent สองฝั่ง** — ไม่ใช่แค่ผู้จัดตั้งค่า ผู้เข้าร่วมต้องเลือกเองได้ว่าจะคุยกับใคร เปิดเผยข้อมูลอะไร
- **Reuse ก่อนเสมอ** — ของที่ reuse บ่อยสุด: websocket broadcast, presence, analytics event, แมป Tiled, form builder

## ลำดับ Core / Cut

ถ้าไม่ทัน ตัดจากล่างขึ้นบน (ข้อ 1–5 ห้ามตัด)

1. ⭐ โลก 2D: เดินในฮอลล์ + บูธ + proximity voice/text
2. ⭐ หน้าบูธ + poster viewer + เสียงโซนบูธ + แชร์จอ
3. ⭐ ค้นหา/กรองผลงาน → ไปบูธทันที
4. ⭐ Judging: rubric + ให้คะแนนในบูธ + รวมคะแนน
5. ⭐ Analytics หลังงาน + feedback ถึงผู้นำเสนอ
6. สร้างฮอลล์อัตโนมัติจาก CSV · Staff panel ในฮอลล์ · Exhibition หลังงาน
7. Popular Vote · form builder
8. 🤖 AI ผู้ช่วยตอบเรื่องผลงาน · AI สรุป feedback · AI import ผลงาน

10. 3D viewer · กล้องผู้นำเสนอ · reaction · map editor · ส่วนที่เหลือ

## User Flow

**แนวคิด** — แยก 3 เรื่องไม่ปนกัน: **บัญชี** (login + onboarding ครั้งเดียว ใช้ได้ทุกงาน) · **role ในงาน** (Staff / Presenter / Judge ได้จากคำเชิญ) · **การเข้างาน** (กด Interested ก่อนงานได้ · ทุก role กรอกฟอร์มเข้างานตอนเข้าครั้งแรก)

**A. Staff (เจ้าของงาน)**
1. login → Create event (Draft): ข้อมูลงาน · เวลา (เริ่มทันที / ตั้งเวลา · เวลาจบไม่บังคับ) · จำกัดโดเมน (ไม่บังคับ) · module · เลือกฮอลล์ preset
2. เพิ่มผลงาน: manual · CSV/XLSX · ฟอร์มให้ Presenter ส่งเอง · AI import — ข้อมูลแค่โครง (ชื่อ · หมวด · อีเมลสมาชิก) Presenter กรอกรายละเอียดเอง
3. ใส่อีเมล Judge + สร้าง rubric · ตั้งคำถามในฟอร์มเข้างาน / survey หลังงาน (ไม่บังคับ)
4. Publish → ระบบส่งคำเชิญ · หน้างานเปิดให้กด Interested
5. วันงาน: ฮอลล์เปิดตามเวลาหรือกดเปิดเอง → ดูแลผ่าน Staff panel ในฮอลล์ · assign role ระหว่างงานได้ (เช่น สร้างบูธเปล่าแล้วให้ Visitor เป็น Presenter)
6. ปิดรอบ judging → ประกาศผล → งานเข้า Exhibition → analytics

**B. Presenter**
1. ได้อีเมลเชิญ → กดลิงก์ → login (+ onboarding ถ้าครั้งแรก) → รับคำเชิญ
2. ไปหน้าบูธของตัวเองทันที → กรอกรายละเอียด + อัปไฟล์ตาม checklist · เชิญเพื่อนร่วมทีมเข้าบูธได้ · เปิด AI assistant ได้ (ถ้าผู้จัดเปิด module)
3. วันงาน: เข้าฮอลล์ → บูธตัวเอง → พูด/แชร์จอให้คนในบูธ · แก้บูธระหว่างงานได้
4. หลังงาน: ดูสถิติ · feedback · คะแนน (หลังประกาศผล)

**C. Judge**
1. ได้อีเมลเชิญ → กดลิงก์ → login → รับคำเชิญ → เห็น rubric + รายการผลงานที่ได้รับมอบหมาย
2. วันงาน: เดินไปบูธ ฟังนำเสนอ → ให้คะแนนในแผงบูธ · แก้ได้จนกว่าปิดรอบ

**D. Visitor** — เข้าจากหน้า Explore หรือลิงก์ที่ผู้จัดแชร์ → ก่อนงานกด `Interested` (login + onboarding ถ้ายังไม่มี) → ฮอลล์เปิดได้ noti ในแอป / ปฏิทินเตือน → `Join` → ฟอร์มเข้างาน (ครั้งแรก) → ฮอลล์

**E. Visitor งานจำกัดโดเมน** — เหมือน D แต่ต้อง login ด้วยอีเมลโดเมนที่ผู้จัดกำหนด (เช่น @kmutt.ac.th) · อีเมลอื่นเห็นงานแต่เข้าไม่ได้

**F. งานเริ่มแล้ว** — ไม่ต้องกด Interested ก่อน · `Join` → login → ฟอร์มเข้างาน → ฮอลล์ · ฮอลล์เต็ม → `Hall is full` (เฉพาะ Visitor)

**G. มือถือ** — ใช้ฮอลล์เดียวกันแบบ responsive: แตะเพื่อเดิน · แผงบูธเป็น bottom sheet

**H. หลังงาน (Exhibition)** — ฮอลล์ยังเดินชมได้ เป็นพื้นที่โชว์ผลงาน · ดูวัสดุในบูธ · ถาม AI assistant · ฝาก feedback ต่อได้

## 1. Account & Platform

- **Auth — บังคับ login ทุกคน** ⭐ M
    - Microsoft (บัญชีองค์กร เช่น @kmutt.ac.th + บัญชีส่วนตัว) · Google · Email link (magic link)
    - **ไม่มี guest / anonymous join** — guest ทำให้ ban ไม่ได้ผล · analytics เพี้ยน · กรรมการ/ผู้นำเสนอยืนยันตัวไม่ได้ · proximity voice ทำให้คนก่อกวนพูดใส่คนอื่นได้ทันที
    - หน้างาน (ข้อมูลงาน + รายการผลงาน) **ดูได้โดยไม่ login** · ต้อง login เมื่อกด Interested เข้าฮอลล์ ฝาก feedback หรือโหวต
    - คนเดียวกัน login ด้วย Google และ Microsoft ที่อีเมลเดียวกัน = บัญชีเดียว (account linking)
    - ⚠️ **JWT ห้ามฝัง event role** — role เปลี่ยนระหว่างงานได้ ต้องเช็คจาก DB/cache ทุกครั้ง
- **Onboarding ครั้งแรก** M — บังคับครั้งเดียวหลัง login ครั้งแรก (~30 วินาที) → เสร็จแล้ว**กลับไปหน้าที่ตั้งใจไป** (หน้างาน / หน้ารับคำเชิญ)
    - บังคับ: ชื่อที่แสดง (เติมจาก OAuth) · preset avatar · ประเภทผู้ใช้ (นักศึกษา · นักเรียน · บริษัท · ศิษย์เก่า · ผู้ปกครอง · อาจารย์) · จังหวัด (วัด SDG)
    - ไม่บังคับ: องค์กร/คณะ · ตำแหน่ง/ชั้นปี · ความสนใจ (หมวดผลงาน ใช้แนะนำบูธ)
    - ทุกช่องต้องบอกว่าเอาไปใช้ทำอะไร
- **คำเชิญ (Invite)** ⭐ M — ใช้กับ role ที่มีสิทธิ์พิเศษ: Staff · Presenter · Judge
    - ส่งทางอีเมลเป็นลิงก์ที่มี token · กดลิงก์ได้ = พิสูจน์ว่าเข้าถึงกล่องอีเมลนั้น
    - อีเมลของบัญชีตรงกับคำเชิญ → รับได้ทันที · ไม่ตรง → แสดง *"This invite is for k\*\*\*@kmutt.ac.th · You're signed in as x@gmail.com"* + `Switch account` / `Accept with this account`
    - รับด้วยบัญชีอื่น → ระบบจำอีเมลที่ถูกเชิญไว้กับบัญชีนั้น · คำเชิญครั้งต่อไปที่อีเมลนี้จับคู่อัตโนมัติ
    - token ใช้ได้ครั้งเดียว · หมดอายุ 14 วัน · staff กด resend (token เก่าใช้ไม่ได้) / ยกเลิกได้
    - ถ้าอีเมลที่เชิญมีบัญชีอยู่แล้ว คำเชิญขึ้นในหน้า Home ของผู้ถูกเชิญด้วย · ฝั่ง staff เห็นแค่ `pending` จนกว่าจะรับ (ไม่เปิดเผยว่าอีเมลไหนมีบัญชี)
    - staff เห็นว่าคำเชิญถูกรับด้วยบัญชีไหน และถอด role ได้
    - จำกัดจำนวนคำเชิญต่อวันต่องาน (กันใช้ระบบส่งอีเมลสแปม) · อีเมลระบุชื่อคนเชิญและชื่องาน · ลง audit log
    - `event_invites(id, event_id, email, roles text[], project_id, token_hash, status, invited_by, accepted_by, expires_at)` · เก็บแค่ hash ของ token
    - `user_emails(user_id, email, verified_at)`
    - Test: บัญชีที่สองกดลิงก์ที่ถูกรับแล้วต้องถูกปฏิเสธ · token หมดอายุ / ถูกยกเลิก · resend แล้วลิงก์เก่าต้องใช้ไม่ได้ · staff ทั่วไปเชิญ STAFF ต้องถูกปฏิเสธ
- **App role** M — `USER` / `PLATFORM ADMIN` · แยกคนละแกนกับ event role
- **Edit Profile** M — โปรไฟล์ชั้นเดียว ไม่เก็บช่องทางติดต่อ
    - แสดงให้คนในงานเห็น: ชื่อ · avatar · องค์กร/คณะ · ตำแหน่ง/ชั้นปี · ความสนใจ
    - ไม่แสดงให้ใครเห็น: ประเภทผู้ใช้ + จังหวัด — ใช้กับ analytics เท่านั้น
    - Preset avatar (ไม่มี custom)
    - ⚠️ PDPA: แจ้งในฟอร์มเข้างานว่าโปรไฟล์จะแสดงให้คนในงานเห็น · ขอ consent ชัดเจน
- **Plan** M 💰 — `events.plan`: `FREE` / `PRO` (งานของผู้จัดที่สมัคร Pro หรือซื้อ Event add-on ให้งานนั้น)
    - Free: คนพร้อมกัน ≤ 50 · core ครบ · judging จำกัด (กรรมการ ≤ 5) · ไม่มี AI · Exhibition ระยะสั้น
    - Pro: คนพร้อมกัน ≤ 300 ต่องาน · ทุกฟีเจอร์ · Exhibition นานขึ้น · Event add-on เพิ่มคน/ฮอลล์เฉพาะงานได้
    - ตัวเลขเป็นค่าตั้งต้น ปรับได้ · ราคาอยู่ใน `connecta-v3.md`
    - Test: Visitor เข้างาน Free เกินที่ที่เหลือต้องถูกปฏิเสธพร้อมข้อความ · เพิ่มกรรมการคนที่ 6 ในงาน Free ต้องถูกปฏิเสธ · อัปเกรดงาน Free เป็น Pro แล้วข้อมูลเดิมต้องอยู่ครบ
- **Billing** C 💰 — Stripe **test mode** เท่านั้น
- **Platform Console** (เฉพาะ PLATFORM ADMIN) C
    - รายการ event ทั้งหมด · ระงับงานที่ผิดกฎ · system health (concurrent, SFU/TURN, storage)
    - ดูแลระดับ platform ผ่าน Console เท่านั้น **ไม่เข้าฮอลล์ของงาน** (ในงานเป็นหน้าที่ของ Staff) · ทุกการใช้อำนาจลง audit log และ staff ของงานเห็นได้

## 2. Event Setup (Staff)

- **Event CRUD** ⭐ M
    - ข้อมูลงาน: ชื่อ · คำอธิบาย · cover · หมวดผลงาน (ไม่บังคับ · ใช้กรอง + จัดโซน) · ตารางเวลาของงาน (agenda แสดงให้ผู้ชมรู้)
    - คนสร้างงาน = **เจ้าของงาน** (`events.owner_id`) และเป็น `STAFF` อัตโนมัติ · เพิ่ม staff ได้หลายคน
    - **Module toggle**: judging · popular vote · feedback · 3D · AI
- **สถานะของงาน** ⭐ M — `Draft → Published → Live → Exhibition → Archived`
    - Draft: ตั้งค่า คนอื่นไม่เห็น · Published: หน้างานเปิด กด Interested ได้ · Live: ฮอลล์เปิด · Exhibition: หลังงาน เดินชมได้ judging ปิด · Archived: ปิดฮอลล์
    - **เวลา**: เริ่มทันที หรือตั้งเวลา · **เวลาจบไม่บังคับ** — ไม่ตั้งก็เปิดจนกว่าผู้จัดปิดเอง
    - ฮอลล์เปิดตามเวลาที่ตั้ง หรือ staff กดเปิด/ปิดเอง · เวลาเป็นกำหนดการให้คนมาพร้อมกัน ไม่ใช่ตัวล็อก
    - **สิ่งที่มีกำหนดตายตัวคือรอบ judging** (ปิดรอบ → ประกาศผล)
    - Exhibition มีระยะเวลาตาม plan → หมดแล้วเข้า Archived
    - `events(…, status, starts_at, ends_at null, hall_open_mode[schedule|manual], exhibition_until)`
- **การเข้าถึงงาน** ⭐ M — **ทุกงานแสดงในหน้า Explore** · มีป้ายบอกประเภทการเข้าถึง
    - `Open to everyone` — ทุกคนที่ login เข้าได้
    - `@kmutt.ac.th only` (โดเมนที่ผู้จัดกำหนด) — เช็คจากอีเมลที่ยืนยันแล้ว (OAuth / magic link) เท่านั้น · อีเมลอื่นเห็นงานแต่ปุ่มเข้าเป็น disabled พร้อมบอกเหตุผล
    - คนที่เข้ามาโดยไม่ควรเข้า staff kick/ban ได้ · role พิเศษใช้คำเชิญ (§1)
    - จำกัดโดเมนใช้กับ **Visitor เท่านั้น** — Staff / Presenter / Judge ที่รับคำเชิญแล้วเข้าได้เสมอ (เช่น กรรมการจากบริษัทที่ใช้ Gmail)
    - `events(…, allowed_domain null)`
    - Test: อีเมลนอกโดเมนที่กำหนดต้องถูกปฏิเสธที่ server (ไม่ใช่แค่ปุ่ม disabled) · Judge ที่รับคำเชิญด้วย Gmail ต้องเข้างานจำกัดโดเมนได้
- **ผลงานและบูธ** ⭐ M — หน้าเดียวจัดการได้ทุกทาง
    - เพิ่ม / แก้ / ลบแบบ manual
    - import **CSV / XLSX** — เป็นโครงข้อมูล: ชื่อผลงาน · หมวด (ถ้างานมีหมวด) · อีเมลสมาชิก · คำอธิบายสั้น (ไม่บังคับ) · ช่องหมวดในฟอร์มส่งผลงานขึ้นเฉพาะงานที่ตั้งหมวดไว้ · มี template ให้ดาวน์โหลด
    - **ฟอร์มส่งผลงาน** ให้ Presenter กรอกเอง
    - อีเมลสมาชิก → ส่งคำเชิญ role `PRESENTER` ของบูธนั้น
    - **AI import** 🤖 S — วางข้อความหรืออัปไฟล์รูปแบบใดก็ได้ → AI จับคู่คอลัมน์กับ field → แสดงตารางให้ตรวจ → กดยืนยันก่อนบันทึก
    - `projects(id, event_id, title, category, abstract, tags text[], cover_url, ai_enabled, booth_slot_id)` · `project_members(project_id, user_id)`
- **ฮอลล์** M
    - เลือก **template ฮอลล์ preset** — `Room` (≤ 12 บูธ ห้องเดียว) · `Hall` (≤ 30 บูธ แถว + ทางเดิน + เวที/workshop/lounge) · ผลงานเกินช่อง → เปิดฮอลล์เพิ่ม
    - preset มีแค่พื้น ผนัง ของตกแต่ง และช่องบูธเป็นกลุ่ม (block) · **บูธวางตอนรันจากรายการผลงาน** แมปเดียวใช้ได้ทุกจำนวน

## 4. Inside the Virtual Event

### 4.1 Roles (ระดับ event · 1 คนมีได้หลาย role)

**เส้นแบ่ง: Staff ทำได้ทุกอย่างที่ย้อนกลับได้ · เฉพาะเจ้าของงาน (`events.owner_id` · 1 คน · เป็น STAFF เสมอ) ทำสิ่งที่ย้อนกลับไม่ได้** — ลบงาน · โอนเจ้าของ · เพิ่ม/ถอด staff · จ่ายเงิน · เผยแพร่งาน · ปิดรอบและประกาศผลคะแนน

| Role | จำนวน | ทำอะไรได้ |
|---|---|---|
| `STAFF` | หลายคน | ทุกอย่างในงาน **ยกเว้นสิ่งที่เฉพาะเจ้าของงาน** — moderation (รวม mute ในบูธ) · แก้ setting · เปิด/ปิดฮอลล์ · assign Presenter/Judge · ดู analytics · ในฮอลล์เหมือนผู้ชมที่มีสิทธิ์ moderation · **ไม่แชร์จอ/เปิดกล้อง** เว้นแต่ assign ตัวเองเป็น Presenter ของบูธนั้นด้วย |
| `PRESENTER` | หลายคน | จัดการบูธของตัวเอง (ก่อนและระหว่างงาน) · เชิญสมาชิกเข้าบูธตัวเอง · แชร์จอ + mute คนในบูธ **เฉพาะในบูธตัวเอง** · เห็น feedback + สถิติ **ของบูธตัวเอง** · เห็นคะแนนกรรมการ**หลังประกาศผล** |
| `JUDGE` | หลายคน | ให้คะแนนผลงานที่ได้รับมอบหมาย · เห็นเฉพาะคะแนนของตัวเอง · แก้ได้จนกว่าปิดรอบ |
| `VISITOR` | — | ค่าเริ่มต้นของทุกคนที่เข้างาน |

- ในเอกสารนี้ "ผู้จัด" = STAFF ทุกคน (รวมเจ้าของงาน)
- ทุก role ต้อง login · **สิทธิ์ = union ของทุก role** ไม่ใช่ hierarchy
- **Role badge บนแมป** — `Staff` · `Presenter` · `Judge` เห็นชัดทั้งบนตัวละครและในรายชื่อ · Visitor ไม่มี badge · มีหลาย role = แสดงหลาย badge · เจ้าของงานแสดงเป็น `Staff` · ⚠️ **ต้องออกจากฝั่ง server** (กันปลอมเป็นกรรมการ/ผู้นำเสนอ)

    - **ระยะเท่า Gather**: เริ่มได้ยินที่ 5 ช่อง · เสียงเต็มภายใน 2 ช่อง แล้วเบาลงตามระยะ · hysteresis ตัดเสียงที่ 7 ช่อง (กันกะพริบที่ขอบ · ยืนยันใน S4) · ใช้ logic เดียวกันกับจอแชร์และกล้องผู้นำเสนอ
- **Proximity text chat** ⭐ M — ลอยเหนือหัว 5–8 วิ แล้วหาย · ไม่เก็บลง DB · สำหรับคนที่เปิดไมค์ไม่ได้
- **เสียงโซนบูธ** ⭐ 🔊 M (spike S5) — ไม่มีโหมดนำเสนอหรือส่งไมค์ · ใครอยากพูดก็พูด (แบบ Zoom/Teams)
    - ทุกคนที่อยู่**ในโซนบูธได้ยินกันชัดเท่ากัน** (เหมือนห้องเดียว ไม่ลดตามระยะ)
    - **เสียงไม่ทะลุทั้งสองทาง** (แบบ private area ของ Gather) — คนในบูธไม่ได้ยินเสียงนอกบูธ (กันเสียงคนคุยเรื่องอื่นหลุดเข้ามา) · คนนอกบูธไม่ได้ยินในบูธ · บอกคนข้างนอกด้วยภาพแทน: ป้าย `● Live` · จำนวนคน · avatar ในบูธ · วงรอบ avatar ของคนที่กำลังพูด (แก้ "ไม่กล้าเข้า")
    - **Presenter ของบูธนั้น + Staff กด mute คนในบูธได้** (แบบ host ใน Zoom) · คนที่ถูก mute เปิดไมค์เองได้ · **ไม่มีใครเปิดไมค์ให้คนอื่นได้** (แนวเดียวกับ Zoom ที่เลิก unmute โดยไม่ถาม) · ⚠️ mute ที่ server ไม่ใช่แค่ฝั่ง client
    - Test: Presenter mute คนในบูธอื่นต้องถูกปฏิเสธ · Visitor mute คนอื่นต้องถูกปฏิเสธ · เดินเข้า/ออกขอบโซนบูธเสียงต้องไม่กะพริบ · บูธมี 15+ คนเปิดไมค์พร้อมกัน · บูธมี 50 คน (ไม่มีคิว จึงต้องรับได้)
- **ไมค์ปิดเป็นค่าเริ่มต้น** S — เข้างานแล้วฟังได้อย่างเดียวจนกว่าจะเปิดเอง · ลดจำนวน track เสียงในบูธที่คนเยอะด้วย
- **Public event chat** S — แผงข้าง ทุกคนในงานเห็น · เก็บใน memory เฉพาะช่วงงาน · ประกาศจากผู้จัด
- **Reaction / emote** C — 👏 ❤️ 😂 ❓ 🔥 · rate limit ~3 ครั้ง/วินาที · ไม่ทำ reaction เชิงลบ
- **⚠️ ไม่มี Direct Message** — ตัดโดยเจตนา การตามต่อหลังงานใช้ "ขอให้ติดต่อกลับ"
- **ข้อแลกเปลี่ยนที่ยอมรับ** — ไม่เก็บ chat = report ย้อนหลังไม่ได้ แลกกับการไม่ต้องแบกภาระ PDPA ของข้อความ

### 4.6 Judging ⭐ M 💰

- กรรมการเห็น **รายการผลงานที่ได้รับมอบหมาย + สถานะ** (ยังไม่ให้ · ให้แล้ว) + ปุ่มไปบูธ
- เดินไปบูธ ฟังนำเสนอ ถามสด → **เปิดแผง rubric ในบูธ** ให้คะแนนรายเกณฑ์ + comment
- คะแนน autosave ทุกครั้งที่แก้ (สถานะ draft) → กด Submit เมื่อให้ครบ · แก้ได้จนกว่าปิดรอบ
- ผู้จัดเห็น**ความคืบหน้า** (กรรมการคนไหนยังให้ไม่ครบ) · เตือนกรรมการได้ · ผลรวมถ่วงน้ำหนักอัตโนมัติ
- เจ้าของงานปิดรอบ → ประกาศผล · ส่ง comment กรรมการให้ผู้นำเสนอ (ผู้จัดกลั่นกรอง/ซ่อนได้ก่อนส่ง)
- `scores(judge_id, project_id, criterion_id, score, updated_at)` — ⚠️ **UNIQUE (judge_id, project_id, criterion_id)**
- `judge_comments(judge_id, project_id, text, visible_to_presenter)`
- ⚠️ ผู้นำเสนอ/ผู้ชม **ห้ามเห็นคะแนนก่อนประกาศ** — ตรวจที่ server
- Test: กรรมการให้คะแนนผลงานที่ไม่ได้รับมอบหมาย · แก้คะแนนหลังปิดรอบ · ลบเกณฑ์ที่มีคะแนนแล้ว · กรรมการ 2 แท็บให้คะแนนพร้อมกัน

### 4.7 Feedback · Popular Vote

- **Feedback** M — ผู้ชมฝากข้อความถึงผลงาน (ตอน Live และ Exhibition) · เลือกไม่ระบุชื่อต่อสาธารณะได้ แต่ staff เห็นว่าใครส่ง · ผู้นำเสนอกดซ่อนได้ · staff ลบได้
- **Popular Vote** S 💰 — โหวตได้ไม่จำกัดจำนวนผลงาน แต่**ผลงานละ 1 ครั้ง** ถอนได้ (แบบ Hack the North) · แสดงเป็น Audience award · ผู้ชมไม่มี rubric (อยากให้ใครให้คะแนนตามเกณฑ์ → เชิญเป็น Judge) · ต้องแวะบูธก่อนโหวตได้ (กันโหวตโดยไม่ดู — ตั้งค่าได้) · ⚠️ **UNIQUE (event_id, user_id, project_id)**
- `feedbacks(id, project_id, author_id, text, is_anonymous, status, created_at)` · `votes(event_id, user_id, project_id)`

### 4.8 Staff panel & Moderation M

- **Staff panel ในฮอลล์** M — overlay สำหรับเรื่องที่ต้องทำทันที: จำนวนคน · สถานะบูธ · report · Announce · mute/kick/ban · สวิตช์ฉุกเฉิน · คลิก avatar แล้ว assign role
- งานตั้งค่า · analytics · ผลคะแนน อยู่ใน dashboard ด้านนอก (เปิดแท็บใหม่จากในฮอลล์ได้)
- **mute / kick (ชั่วคราว) / ban (ถาวร)** — ทำได้โดย STAFF · ban ผูกกับ user_id และตัด session ทันที
- **report** → queue ให้ staff ตรวจ · ลบข้อความและ feedback ที่ไม่เหมาะสม
- **audit log ทุกการกระทำ** — ใครทำอะไรกับใคร เมื่อไหร่ เพราะอะไร
- **สวิตช์ฉุกเฉิน** — ปิดรับคนเข้าใหม่ / ปิดไมค์ทั้งงาน
- ban ได้ผลจริงเพราะบังคับ login

### 4.9 ขอให้ติดต่อกลับ S

- ผู้ชมที่สนใจผลงาน (เช่น บริษัทที่อยากรับฝึกงาน) กดปุ่มในบูธเพื่อฝากช่องทางติดต่อให้ทีม — **ทางเดียว** ไม่มีการแลก contact ระหว่างผู้ชมด้วยกัน
- กรอกตอนกดปุ่ม: อีเมล (เติมจากบัญชี แก้ได้) · เบอร์/LinkedIn/ข้อความสั้น (ไม่บังคับ) — ไม่เก็บใน profile · ⚠️ ต้องมีข้อความข้างปุ่มว่า *"ทีมจะเห็นชื่อ องค์กร และข้อมูลที่คุณกรอก"* (PDPA) · ห้ามใช้คำว่า "สนใจ" ที่กำกวม
- ใช้ได้ทั้งตอน Live และ Exhibition · ผู้นำเสนอเห็นรายชื่อในสรุปบูธ + export CSV · ผู้ชมถอนได้
- `contact_requests(id, project_id, user_id, email, phone, link, message, created_at)` · ⚠️ **UNIQUE (project_id, user_id)**
- Test: ผู้นำเสนอบูธอื่นเห็นรายชื่อของบูธนี้ต้องถูกปฏิเสธ · ถอนแล้วทีมต้องไม่เห็นอีก

### 6.2 AI Features 🤖

**AI ผู้ช่วยตอบเรื่องผลงาน (RAG)** S 💰 — ผู้นำเสนออัปโหลดเอกสาร (โปสเตอร์ · รายงาน · สไลด์) → chunking + embedding เก็บใน **pgvector** → ตอบคำถามผู้ชมตอน**ผู้นำเสนอไม่อยู่ในบูธ** และใน **Exhibition**
- เปิด 2 ชั้น: ผู้จัดเปิด module ระดับงาน → ผู้นำเสนอเปิดของบูธตัวเอง (`projects.ai_enabled`) · ผู้นำเสนอ**ลองถามก่อนเปิดใช้จริง**
- ใช้ไฟล์ชุดเดียวกับในบูธ ไม่ต้องอัปโหลดซ้ำ
- ⚠️ ต้องมี **guardrail** — ตอบเฉพาะจากเอกสารผลงาน ถ้าไม่รู้ต้องบอกว่าไม่รู้ · แสดงว่าเป็นคำตอบจาก AI ไม่ใช่ผู้นำเสนอ
- AI ตอบไม่ได้ → แนะนำให้ฝาก feedback หรือกด "ขอให้ติดต่อกลับ"
- จัดเป็น Intermediate–Advance ได้เพราะมี retrieval pipeline ของตัวเอง ไม่ใช่ prompt เปล่า

**AI สรุป feedback** S — รวม feedback ผู้ชม + comment กรรมการ → สรุปจุดแข็ง/จุดที่ควรปรับให้ผู้นำเสนอ (แก้ pain "feedback เยอะแต่เอาไปใช้ยาก / feedback น้อย")

**AI import ผลงาน** S — ดู §2 ผลงานและบูธ · คนตรวจก่อนบันทึกเสมอ

- ต้องวัด **ต้นทุนต่องาน** ของ AI เพราะเข้าไปอยู่ในโครงสร้างต้นทุนของ business model
