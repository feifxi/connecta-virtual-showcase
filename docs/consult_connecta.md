## 2. คำถามและคำตอบ (เรียงตามลำดับในการสอบ)

> 🔴 = ถูกถามซ้ำหลายรอบ/กระทบแกนของโครงงาน · 🟠 = ตอบกำกวมหรือยังไม่มีคำตอบ · 🟢 = ตอบได้ดี

### Q1 🔴 ต่างจากเจ้าอื่นในตลาดยังไง (Gather / WorkAdventure)

**คำตอบที่ให้**: Gather เป็น *virtual office* (ฝั่งฝรั่ง) เราโฟกัส *event* · ถ้าใช้ Gather ผู้จัดต้องสร้างแมปเอง จัดลงทะเบียน ทำโฆษณาเอง · ของเรามี map preset, ลงทะเบียน, agenda ในตัว ผู้จัดไม่ต้องคราฟแมปเองทั้งหมด · ส่วน **WorkAdventure — ตอบว่าไม่ค่อยมีข้อมูล** (ข้อมูลหลักมีแค่ Gather)

**กรรมการ**: ในตลาดมีหลายเจ้า ทั้งพรีเมียมและ open source · ถ้าจะเอาขึ้นเว็บให้คนใช้ ต้องมี**ข้อมูลที่บอกได้ว่าจุดเด่นต่างจากเจ้าอื่นยังไง** เตรียมไว้ตอบทั้งคนที่เราไปเสนอ และอาจารย์ · ถ้าดูข้อมูลประกอบ จะเห็นว่าคู่แข่งอาจไม่ได้โฟกัสแค่ meeting และไม่ได้มีเจ้าเดียว · *"ถ้าแค่บอกว่าออฟไลน์เสียเวลาเดินทางเราจัดออนไลน์ดีกว่า เครื่องมือจะเยอะมาก"* — คือข้อนี้ไม่พอเป็นคำตอบ

→ **พลาด**: ตอบได้แค่ระดับ "virtual office vs event" และไม่มีข้อมูลเทียบรายเจ้า

### Q2 🟢 มี template ของรูปแบบงานไหม (ตำแหน่งเวที บูธ)

มี map preset ให้เลือกหลายแบบ · **กรรมการ**: ถ้ามีจุดต่างพวกนี้ (เช่น แลกนามบัตร) แล้วชูขึ้นมาก็น่าสนใจขึ้น แต่ถ้าชูแค่ "ออนไลน์ประหยัดการเดินทาง" จะแพ้เครื่องมืออื่น

### Q3 🟠 ทำทันไหม (ฟีเจอร์เยอะ)

**คำตอบ**: ทีมประเมินว่าทัน เพราะ (1) ใช้ AI ช่วยเขียน (2) ส่วนยาก (เสียง/วิดีโอ) ใช้ library ไม่ได้ทำเอง มี doc/ตัวอย่าง/โปรเจคอ้างอิง (3) **มีแผนสำรอง ตัดฟีเจอร์ที่ไม่สำคัญ** · *"ตอนนี้เหมือนเรายัดทุกอย่างที่เรานึกออกเข้าไป"*

**กรรมการ**: ควรเตรียมตั้งแต่แรกเลยว่าอันไหนเป็นฟีเจอร์หลัก อันไหนเป็นฟีเจอร์หลัง (ที่อาจถูกตัด)

→ **พลาด**: ยอมรับเองว่ายังไม่ได้จัดลำดับ core / cut

### Q4 🔴 ขายใคร / โมเดลธุรกิจ

**คำตอบ**: *"ใครก็จัดได้ จะผมจัดกับเพื่อนก็ได้"* แต่เน้นสถาบันการศึกษา (open house) และสมาคมที่จัด meeting บ่อย

**กรรมการ (ลงลึก)**: สมมติสมาคมศิษย์เก่าจ่าย 500,000 บาทจัด 3 วัน — **จ่ายแล้วได้แพลตฟอร์มไปใช้เอง หรือเรามีทีมหลังบ้านคอยดูแลให้?** · คำตอบที่ให้: ผู้จัดกรอกฟอร์มสร้างอีเวนต์ ส่วน operation ต่างๆ *"เป็นหน้าที่ของเรา"*, *"ผมทำให้"*, ผู้จัดมาดูทีหลังอย่างเดียว

→ 🟠 **พลาด: คำตอบกำกวมและขัดกับ proposal** — proposal บอกว่าเป็น **self-service** (ผู้จัดสร้างและจัดการเอง) แต่คำตอบฟังเหมือนทีมเป็นคนรัน operation ให้ ซึ่งกรรมการอาจเข้าใจว่าเป็นบริการรับจัดงาน (agency) · และ "ใครก็จัดได้" คือสิ่งที่กรรมการเตือนซ้ำในช่วงท้าย

### Q5 🟠 มุมมอง 2D กับสินค้าที่ต้องดูรายละเอียด (เสื้อผ้า / ของจริง)

**คำตอบ**: ไม่เหมาะกับทุกงาน (เช่น motor show ที่ต้องสัมผัสจริง) · เหมาะกับงานที่อัปโหลดไฟล์/วิดีโอ/แชร์จอ เช่น โปสเตอร์ งานนักศึกษา · อาจ design เพิ่มให้เป็น 3D เฉพาะส่วนนี้

**กรรมการเสนอ**: ถ้าพัฒนาไปถึงขั้นสินทรัพย์เป็น 3D (เหมือน virtual tour ของคอนโด) เพิ่มเป็น option/บริการสร้างโมเดล 3D ให้ organizer ได้ · **ทีมตอบ**: คิดไว้แล้วทั้ง 2 อย่าง แต่ติดเรื่องเวลา (ทีม 3 คน)

### Q6 🟠 การจัดการเสียงตอน speaker พูด

**คำตอบ**: แยกช่องเสียง **speaker** กับ **คนรอบตัว** ปรับดัง-เบา หรือปิดเสียง speaker เฉพาะของตัวเองเพื่อคุยกับคนรอบตัวได้ · organizer ตั้งตอนสร้างงานได้ว่าให้ปิดไมค์ทุกคน เปิดได้เฉพาะโซนที่กำหนด

**กรรมการเสนอ** 💭 ถ้าอยู่กันเป็นโต๊ะ 4 คน ควร**เลือกคนที่จะคุยด้วยเป็นกลุ่ม** (ติ๊กเลือกกี่คน) คนที่เหลือไม่ได้ยิน ไม่ใช่ได้ยินทุกคนรอบตัว

**ทีมตอบ**: เคยมีฟีเจอร์ "กระซิบ" ที่คุยเป็นกลุ่มส่วนตัวได้ แต่**ตัดไปเพราะเวลา** ใช้ห้องส่วนตัว 2 คน (Meeting Room) แทน · *ตอนอธิบายยังบอกว่า "ผมไม่ได้มีรูปมาก่อน"* → ไม่มี mock-up ให้เห็นดีไซน์

### Q7 🟠 ถ้าไม่รู้จักใครเลย จะเลือกคุยกับใครยังไง → เรื่องความยินยอมและ PDPA

**คำตอบ**: ไปดูโปรไฟล์ (เป็นใคร ทำงานอะไร สนใจอะไร) แล้วเดินเข้าไปคุยได้เลย

**กรรมการ (2 ประเด็น)**
1. **PDPA**: ต้องดูว่าผู้เข้าร่วมให้ consent ที่จะแสดงข้อมูล (ชื่อ นามสกุล ตำแหน่ง เบอร์โทร) ให้คนอื่นเห็นแล้วเข้ามาคุยหรือยัง ถ้าไม่ได้ขอให้ชัด อาจผิด
2. **ผู้ถูกเข้ามาคุย**: ถ้าจะคุย 1:1 หรือคุยละแวกใกล้ๆ ฝั่งผู้ถูกขอเขาต้องกดยินยอมไหม? *"ถ้าพี่ตั้งใจไปฟังงาน แล้วอยู่ดีๆ ใครก็ไม่รู้มาคุยเต็มไปหมด โดยที่เลือกไม่ได้ว่าอยากคุยหรือไม่"*

**ทีมตอบ**: เป็น option ของผู้จัดว่าจะให้คุยอิสระหรือต้องขอก่อน ตั้งตอนสร้างงานได้

**กรรมการตอบกลับ**: *"ไม่ใช่แค่ความต้องการของผู้จัด ต้องมีความต้องการของผู้เข้าร่วมด้วย"* · **main comment**: ให้วิเคราะห์ฟีเจอร์ที่อยากทำแต่ละตัวว่าทำอะไรได้ มีความเสี่ยงอะไร แล้วค่อยสรุปว่าทำอะไรตามลำดับความสำคัญ

### Q8 🟢 ฝั่งผู้จัด: หลังบ้านเป็นยังไง (role / เมนู)

**คำตอบ**: ตั้งค่างานบนเว็บก่อนเข้า world ได้ · มี role ชัด (user / organizer / staff) · staff ได้ UI ใน event เพื่อ moderate และปรับ setting แบบ realtime · กรรมการไม่ถามต่อ (เป็นข้อที่ตอบผ่าน)

### Q9 🔴🔴 **Value จริงของ solution คืออะไร** (ถามหนักที่สุด)

**ประเด็นจากกรรมการ (พูดต่อเนื่องหลายรอบ)**
1. ถ้า value คือ **content ของสัมมนา** — คนซื้อตั๋วสัมมนา ส่วนใหญ่เหตุผลจริงคือ *ดูย้อนหลังได้* เพราะแบ่งตัวดู 2 session พร้อมกันไม่ได้ → แล้วระบบเราต่างจาก **แพลตฟอร์มดูย้อนหลังทั่วไป** ยังไง
2. **เรื่องราคา**: ถ้าผู้จัดจ้างเรา ถ้าถูกกว่าก็อาจเลือก แต่ถ้า**แพงกว่าเพราะลูกเล่นเยอะ** ก็จะไม่ impact กลุ่มจัด conference
3. งานที่มีเหตุผลเรื่อง "ต้องไปตอนนั้น" (เช่น live ขายของ ราคาพิเศษช่วงเวลาเดียว) ต่างจากงานสัมมนา — ต้องดูว่า value จริงคืออะไร
4. นอกจากได้จัดงาน ผู้จัดได้อะไรกลับมา เช่น **data** → ทำ business matching ต่อได้ไหม จัด session เล็กๆ จับคู่ธุรกิจ — งาน event จริงมี "หลังบ้าน" ที่เอาข้อมูลไปทำต่อ นั่นคือเหตุผลที่บังคับลงทะเบียน
5. **ทีมเองตอบ value ไม่ได้ ไม่ใช่ลูกค้า** → แนะนำให้ไปคุยกับผู้จัดจริง (ถ้าโฟกัสมหาลัยก็ไปคุยกับคณะ) เขียนฟีเจอร์ทั้งหมดใส่กระดาษให้เขา**ให้ priority** ว่าอะไรจำเป็นจริง แล้วตัดที่ไม่จำเป็นออก

### Q10 🔴🔴 ถ้าหากลุ่มที่ต้องการไม่เจอ ก็แข่งกับทุกคน (MS365 / Google Workspace)

**กรรมการ**: ถ้าไม่หา value เฉพาะกลุ่มให้เจอ เราก็จะเป็นแค่ระบบจัดสัมมนาออนไลน์ + แมป 2D แล้วคู่แข่งคือ**ทุกคนที่จัดสัมมนาออนไลน์ได้** · องค์กรที่ใช้ **Microsoft 365 / Google Workspace** อยู่แล้ว สร้างสัมมนาออนไลน์ได้ มีลงทะเบียน มีควบคุมสิทธิ์พูด มีสรุปหลังงาน **"จะเรียกว่าฟรีก็ได้ เพราะจ่าย subscription รายปีอยู่แล้ว"** → *"ทำไมต้องมาเสียเงินซื้อ ในเมื่อมีเครื่องมือฟรีที่ตอบโจทย์"*

### Q11 🔴 **Analytics หลังงาน — ข้อที่กรรมการมองว่าสำคัญที่สุด**

**กรรมการ (ข้อแนะนำ)**: แพลตฟอร์มอื่นอาจคล้ายกัน แต่สิ่งที่ไม่เห็นคือ**การรายงาน data ท้ายงาน** เช่น ผู้ชายผู้หญิง อายุ ประเทศ ใครสนใจ สินค้าไหนคนดูเยอะ — *"เอาไปเล่นมาร์เก็ตติ้งต่อได้"* · *"พี่มองว่าตรงนี้เป็นสิ่งล้ำค่าที่สุดที่ product น้องมอบให้คนที่ใช้ระบบได้ ... อาจเป็น key point ที่วินเจ้าอื่น"* · และถ้าชูตรงนี้เป็นอีกหน้าหนึ่ง *"พี่ว่าเยี่ยม"*

**ทีมตอบ**: มี post analytics อยู่แล้ว (จำนวนผู้เข้าร่วม คนคุยกับ staff/บูธ) และมี billboard ของ sponsor อยู่ตอนนี้ แต่ยังไม่ได้ชู

💭 **ช่องว่างของเรา**: ฟอร์มลงทะเบียนในแผนเก็บ *องค์กร · ตำแหน่ง · ความสนใจ* ไม่ได้เก็บ **อายุ / เพศ / ประเทศ** ตามที่กรรมการยกตัวอย่าง (และถ้าจะเก็บต้องชั่งกับ PDPA ที่กรรมการเตือนใน Q7)

### Q12 🟢 ผลลัพธ์: ทีมสรุปเองว่าจะ "โฟกัสให้แคบลง"

**ทีมเสนอ**: แพลตฟอร์ม general เกินไป ไม่เจาะประเภท → ลอง focus ที่ **การนำเสนอผลงาน** (บูธ นิทรรศการ อาจเป็น 3D + analytics) แทนที่จะเป็น event ทุกแบบ · ยกเคส NeurIPS ที่ *ช่วง meeting ใช้ Zoom แต่ช่วงโปสเตอร์หันมาใช้ 2D เพราะคนอยากเดินดูและเจอคนในงาน* ส่วนที่เป็นการนำเสนออย่างเดียวไม่ต้องการหลายวงคุย ก็ยังใช้ Zoom → "อาจลด scope ไปโฟกัสพาร์ทที่เครื่องมือเดิมยังทำไม่ดี" · และ "ลอง focus แต่ละอุตสาหกรรมไปเลย"

**กรรมการยืนยัน (ปิดท้ายของทีมเรา)**: ใช่ ควรโฟกัสให้ดีสักพัก · ยกอุปมา — *บริษัทที่จ้างพนักงานจ่ายเงินเดือนทุกวัน แล้วนั่งคิดว่าวันนี้จะทำอะไรดี โดยยังไม่เคยรู้ว่าจะทำให้ใคร ใครมี pain point แล้วยอมจ่าย* → ถ้าไม่ตีกรอบ จะกลายเป็น **ระบบระดับโลกร้อยฟีเจอร์ที่ไม่ตอบใคร** · แนะนำให้ดูว่า **ใครเกี่ยวข้อง ความต้องการแต่ละกลุ่มคืออะไร แล้วโฟกัสกลุ่มนั้นก่อน** (ตัวอย่าง: ตลาดนำเสนอสินค้าอุตสาหกรรมยานยนต์ หรือซอฟต์แวร์) · เมื่อมีกรอบ ฟีเจอร์ที่ต้องพัฒนาก็ชัด ไม่ต้องเสียเวลาทำสิ่งที่ไม่ใช้ · *"ตอนนี้ยังไม่ได้ตีกรอบว่าคนทำอะไรให้ใคร"*

## 4. สิ่งที่กรรมการชอบ / ตอบได้ดี

- **ไอเดียน่ารักและน่าสนใจ** — พอพูดถึงฟีเจอร์เสริม (แลกนามบัตร) กรรมการบอกว่าน่าสนใจขึ้นเทียบกับสัมมนาที่ฟังอย่างเดียว
- **Analytics หลังงาน** — กรรมการเห็นเป็นจุดที่อาจชนะเจ้าอื่น
- **หลังบ้าน/role** ตอบแล้วไม่มีคำถามต่อ
- **การยกเคสจริง (NeurIPS) + ยอมรับข้อจำกัด** (ไม่เหมาะ motor show) ทำให้การเสนอดูไม่เคลมเกิน
- **ทีมวิเคราะห์เองได้ระหว่างสอบ** ว่าควรลด scope ไปที่ "การนำเสนอผลงาน" และกรรมการเห็นด้วย

## 5. ข้อเสนอสิ่งที่ควรทำต่อ (💭 ข้อเสนอของผม ยังไม่ได้ตกลงกับทีม และยังไม่ได้แก้ไฟล์ใด)

1. **เขียน "value ของผู้จัด" ให้ตอบได้ใน 2 ประโยค** พร้อมคำตอบ 3 ข้อที่ถูกถาม: *ต่างจากคู่แข่ง · ต่างจากดูย้อนหลัง · ทำไมไม่ใช้ MS365/Google Workspace ฟรี* — โดยบอกตรงๆ ว่าเหมาะกับงานที่คุณค่าอยู่ที่การพบปะ ไม่ใช่งานบรรยาย
2. **ตัดสินใจ vertical อันดับ 1** (กรรมการเห็นพ้องกับที่ทีมเสนอเอง: งานนำเสนอผลงาน/แสดงผลงานนักศึกษา) แล้วจัด Target Group ใหม่ตามนั้น
3. **ชู analytics หลังงานเป็นจุดขาย** และตัดสินใจเรื่องข้อมูลที่จะเก็บ (อายุ/เพศ/ประเทศ ฯลฯ) ให้สมดุลกับ PDPA
4. **ทำ consent สองฝั่ง**: ผู้เข้าร่วมเลือกได้ว่าจะให้ใครเข้ามาคุยแบบไหน (เช่น โหมดไม่รบกวน / ขอก่อนคุย) ไม่ใช่ให้ผู้จัดเป็นคนตั้งอย่างเดียว
5. **ทำรายการ core / cut** ที่ทีมตกลงกัน พร้อมลำดับที่จะตัดถ้าไม่ทัน
6. **ซ้อมคำตอบเรื่องโมเดลธุรกิจ**: self-service ผู้จัดสร้างและรันเอง (ไม่ใช่ทีมรับจัดงาน) · ราคาต่องานตามความจุ
7. **ทำ mock-up / ภาพหน้าจอ** อย่างน้อย: หน้าแมป, ตอนคุยกลุ่ม, หน้า analytics
8. **ไปคุยผู้จัดจริง** (คณะ/มหาลัย) โดยเอาฟีเจอร์ใส่กระดาษให้เขาจัดลำดับ ตามที่กรรมการแนะนำ
9. **หาข้อมูลเทียบคู่แข่งรายเจ้า** รวม WorkAdventure และชุดเครื่องมือที่องค์กรมีอยู่แล้ว (MS Teams / Google Meet webinar)
